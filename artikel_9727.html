The standard route is the provider's platform API with an API key.

One common confusion is worth clearing up. Some subscriptions come with API-related benefits, and some coding clients support both subscription sign-in and API keys. GoodExts has a separate explainer on what a ChatGPT subscription does and doesn't give you for API access. In short, an official API integration, a signed-in client like Codex, and a local bridge each use different connections and credentials. Before comparing costs, check which one your tool actually uses.

The other route runs locally. A small service on your computer talks to an AI client you are already signed in to, and exposes one local interface that your own tools can call.

Some design details are worth borrowing even if you build your own bridge:

AgentRelay is free and doesn't sell model credits. The application source is private.

XFollower is a GoodExts Chrome extension for daily X operations: followers, follow-up queues, saved posts and writing knowledge. It's a good concrete example because it uses the bridge for several separate jobs. The full guide is in Connect XFollower to AgentRelay. Condensed:

1. Start AgentRelay and your AI client. Install and sign in to the client you want to use. On the AgentRelay home screen, confirm the service is running and copy its base address and access token. The default is http://127.0.0.1:8787, but use the port actually shown.

2. Allow the extension to reach the local service. The default Allow all origins setting usually means no per-extension setup, though API requests still need the token. If you turn that setting off, add the extension's origin (chrome-extension://) to AgentRelay's allowed origins.

3. Enter the connection and pick a conversation. In XFollower, open System settings â†’ AI engines. Enter the base address and token without appending /codex, /grokbot or /antigravity. Then choose an engine and read its conversations. The three engines share the address and token, but each keeps its own conversation selection.

4. Test, save, reopen. Use a dedicated test conversation and click Test and save once. This sends a real verification message and uses your allowance. Then reopen the settings and confirm the engine, conversation and verified status.

5. Route each feature to its own conversation. For example, use one conversation for collecting and classifying posts and another for brand replies. Inspect a small batch before enabling anything automatic. A successful connection doesn't enable posting.

If the panel closes or the service restarts, query the original task first. Pending doesn't mean failed, and blindly resending creates duplicates.

To wire your own extension or app to AgentRelay, the AgentRelay page offers an integration skill to download: a ZIP containing a SKILL.md, a client, and test tools that need Node.js 22+. You give it to a coding assistant that can read local files. The assistant checks the service, binds a conversation, and sends two harmless test messages. Those messages verify that context carries over, that bindings survive a reopen, and that recovery works by querying the original job instead of resending.

That test plan is worth copying even if you never use the tool.

The bridge is free, but the workflow isn't automatically cheaper. Count the time to prepare batches, any model costs or plan upgrades, and the time spent correcting results. No fixed savings percentage fits everyone. A bridge is worth it when it removes enough repeated transfer work for your task.
