Stopping a Website AI Chat Agent From Making Things Up

Tanggal: 2026-11-26

A website chat agent that answers most questions well and invents a refund policy once a week is worse than no chat agent. The visitor screenshots the wrong answer, and now your support team has to honor it or argue about it.

Picking a better model doesn't fix this. Four boring layers do: what the agent is allowed to read, what it is told never to say, what it is allowed to do, and who reads the transcripts afterwards. Here is how we set up each one.

Most bad answers come from bad source material, not from the model. The usual mistake is pointing the agent at the whole website and a folder of old PDFs. That folder holds the 2023 price list, a promo that ended, and three versions of the cancellation policy.

The last line matters most. "I'm not sure, let me get someone who knows" is a perfectly good answer. Agents that are never allowed to say it will make something up.

An agent that can only answer questions can only embarrass you. An agent that can write to your CRM, book calendars and send texts can do real damage. Give it the smallest set of tools the job needs:

If your platform lets you, log every tool call with the conversation ID. When something goes wrong you want to see exactly what the agent did, not guess.

For the first month, someone reads transcripts every week. Not all of them: sort by the ones where the visitor asked for a person, left mid-conversation, or the agent said "I'm not sure". Those three groups show you nearly every gap in the knowledge base.

Each finding turns into one of three fixes: add or correct a knowledge base answer, add a prohibition, or remove a tool. Then re-test the same question by hand.

Visitors should know they're chatting with an AI and how to reach a person. It's good manners, and in the EU the AI Act's transparency rules for chatbots apply from August 2, 2026. A first message like "Hi, I'm the AI assistant for [business]. I can answer questions and book a call, or connect you with the team" covers it.

None of this is specific to one platform. The same four layers apply whether the agent runs on GoHighLevel Conversation AI, a chatbot builder or your own code calling a model API.
