Shipping in-browser WASM background removal without crashing Safari tabs (+ an open real-device latency dataset)

Tanggal: 2026-11-13

Over the past month I built and shipped remove.ac, an image background remover split into two explicit execution paths: a free in-browser WebAssembly studio where image bytes stay inside the tab, and an optional stateless Cloud GPU API (POST /v1.0/removebg) compatible with remove.bg payloads.

Running a 1024px segmentation model (onnxruntime-web WASM + guided-filter hair refinement) inside real users' browsers surfaced a few bugs that never showed up on an M-series MacBook during development. Here is what broke, how we fixed it, and the raw telemetry we collected from 2,000+ production runs.

Dropping references to temporary elements in React was enough in Chromium, but iOS and macOS Safari kept hundreds of megabytes of backing-store memory pinned across batch runs. Explicitly zeroing dimensions (canvas.width = 0; canvas.height = 0) in teardown routines reclaimed memory immediately and stopped mobile tab reloads during 50-image ZIP batches on /batch.

On a 12 MP product photo, storing 10 undo snapshots as raw RGBA ImageData eats ~480 MB on its own. For the local Erase / Restore / Smart Brush and point/box subject selector, we switched to replaying stroke vectors on top of a rolling checkpoint canvas, capping undo history at 12 steps within a 64 MB ceiling.

A subtle trust bug in "hybrid" web tools is catching an out-of-memory WASM error and quietly uploading the file to a cloud worker so the task succeeds. If someone picked on-device processing for an ID scan or unreleased product shot, silent fallback violates the whole point. On remove.ac, local failures stay local; Cloud GPU runs only when a signed-in user clicks it or calls the API with an X-Api-Key (rac_live_...).

Standard serverless HTTP gateways choke around 4.5 MB, which fails as soon as a studio photographer outputs a 15 MB lossless PNG. Instead of staging uploads in an object bucket, our zero-dependency SDKs and CLI request a single-use HMAC ticket from POST /v1.0/removebg/ticket (placing a Postgres FEFO credit hold) and stream up to 25 MB / 40 MP directly into volatile GPU worker RAM. If inference errors out or times out, the credit hold releases automatically at zero cost.

If you want to poke at the browser WASM studio (no login wall) or test /v1.0/removebg with the free signup credit, everything is live at https://remove.ac. Happy to share details on the guided-filter worker pipeline or the Postgres FEFO ledger SQL!
