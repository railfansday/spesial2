Transformer-based Encoder-Decoder Models

Tanggal: 2026-11-13

The transformer-based encoder-decoder model was introduced by Vaswani et al. in the famous Attention is all you need paper and is today the de-facto standard encoder-decoder architecture in natural language processing (NLP).

Recently, there has been a lot of research on different pre-training objectives for transformer-based encoder-decoder models, e.g. T5, Bart, Pegasus, ProphetNet, Marge, etc..., but the model architecture has stayed largely the same.

The goal of the blog post is to give an in-detail explanation of how the transformer-based encoder-decoder architecture models sequence-to-sequence problems. We will focus on the mathematical model defined by the architecture and how the model can be used in inference. Along the way, we will give some background on sequence-to-sequence models in NLP and break down the transformer-based encoder-decoder architecture into its encoder and decoder parts. We provide many illustrations and establish the link between the theory of transformer-based encoder-decoder models and their practical usage in 🤗Transformers for inference. Note that this blog post does not explain how such models can be trained - this will be the topic of a future blog post.

Transformer-based encoder-decoder models are the result of years of research on representation learning and model architectures. This notebook provides a short summary of the history of neural encoder-decoder models. For more context, the reader is advised to read this awesome blog post by Sebastion Ruder. Additionally, a basic understanding of the self-attention architecture is recommended. The following blog post by Jay Alammar serves as a good refresher on the original Transformer model here.

At the time of writing this notebook, 🤗Transformers comprises the encoder-decoder models T5, Bart, MarianMT, and Pegasus, which are summarized in the docs under model summaries.

Tasks in natural language generation (NLG), a subfield of NLP, are best expressed as sequence-to-sequence problems. Such tasks can be defined as finding a model that maps a sequence of input words to a sequence of target words. Some classic examples are summarization and translation. In the following, we assume that each word is encoded into a vector representation. nnn input words can then be represented as a sequence of nnn input vectors:

X1:n={x1,…,xn}.\mathbf{X}_{1:n} = \{\mathbf{x}_1, \ldots, \mathbf{x}_n\}.X1:n​={x1​,…,xn​}.

Consequently, sequence-to-sequence problems can be solved by finding a mapping fff from an input sequence of nnn vectors X1:n\mathbf{X}_{1:n}X1:n​ to a sequence of mmm target vectors Y1:m\mathbf{Y}_{1:m}Y1:m​, whereas the number of target vectors mmm is unknown apriori and depends on the input sequence:

f:X1:n→Y1:m. f: \mathbf{X}_{1:n} \to \mathbf{Y}_{1:m}. f:X1:n​→Y1:m​.

Sutskever et al. (2014) noted that deep neural networks (DNN)s, "*despite their flexibility and power can only define a mapping whose inputs and targets can be sensibly encoded with vectors of fixed dimensionality.*" 1{}^11

Using a DNN model 2{}^22 to solve sequence-to-sequence problems would therefore mean that the number of target vectors mmm has to be known apriori and would have to be independent of the input X1:n\mathbf{X}_{1:n}X1:n​. This is suboptimal because, for tasks in NLG, the number of target words usually depends on the input X1:n\mathbf{X}_{1:n}X1:n​ and not just on the input length nnn. E.g., an article of 1000 words can be summarized to both 200 words and 100 words depending on its content.

In 2014, Cho et al. and Sutskever et al. proposed to use an encoder-decoder model purely based on recurrent neural networks (RNNs) for sequence-to-sequence tasks. In contrast to DNNS, RNNs are capable of modeling a mapping to a variable number of target vectors. Let's dive a bit deeper into the functioning of RNN-based encoder-decoder models.

During inference, the encoder RNN encodes an input sequence X1:n\mathbf{X}_{1:n}X1:n​ by successively updating its hidden state 3{}^33. After having processed the last input vector xn\mathbf{x}_nxn​, the encoder's hidden state defines the input encoding c\mathbf{c}c. Thus, the encoder defines the mapping:

fθenc:X1:n→c. f_{\theta_{enc}}: \mathbf{X}_{1:n} \to \mathbf{c}. fθenc​​:X1:n​→c.

Then, the decoder's hidden state is initialized with the input encoding and during inference, the decoder RNN is used to auto-regressively generate the target sequence. Let's explain.

Mathematically, the decoder defines the probability distribution of a target sequence Y1:m\mathbf{Y}_{1:m}Y1:m​ given the hidden state c\mathbf{c}c:

pθdec(Y1:m∣c). p_{\theta_{dec}}(\mathbf{Y}_{1:m} |\mathbf{c}). pθdec​​(Y1:m​∣c).

By Bayes' rule the distribution can be decomposed into conditional distributions of single target vectors as follows:

pθdec(Y1:m∣c)=∏i=1mpθdec(yi∣Y0:i−1,c). p_{\theta_{dec}}(\mathbf{Y}_{1:m} |\mathbf{c}) = \prod_{i=1}^{m} p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c}). pθdec​​(Y1:m​∣c)=i=1∏m​pθdec​​(yi​∣Y0:i−1​,c).

Thus, if the architecture can model the conditional distribution of the next target vector, given all previous target vectors:

pθdec(yi∣Y0:i−1,c),∀i∈{1,…,m}, p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c}), \forall i \in \{1, \ldots, m\},pθdec​​(yi​∣Y0:i−1​,c),∀i∈{1,…,m},

then it can model the distribution of any target vector sequence given the hidden state c\mathbf{c}c by simply multiplying all conditional probabilities.

So how does the RNN-based decoder architecture model pθdec(yi∣Y0:i−1,c)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c})pθdec​​(yi​∣Y0:i−1​,c)?

In computational terms, the model sequentially maps the previous inner hidden state ci−1\mathbf{c}_{i-1}ci−1​ and the previous target vector yi−1\mathbf{y}_{i-1}yi−1​ to the current inner hidden state ci\mathbf{c}_ici​ and a logit vector li\mathbf{l}_ili​ (shown in dark red below):

Subsequently, the softmax operation is used to transform the logit vector li\mathbf{l}_ili​ to a conditional probablity distribution of the next target vector:

p(yi∣li)=Softmax(li), with li=fθdec(yi−1,cprev). p(\mathbf{y}_i | \mathbf{l}_i) = \textbf{Softmax}(\mathbf{l}_i), \text{ with } \mathbf{l}_i = f_{\theta_{\text{dec}}}(\mathbf{y}_{i-1}, \mathbf{c}_{\text{prev}}). p(yi​∣li​)=Softmax(li​), with li​=fθdec​​(yi−1​,cprev​).

From the above equation, we can see that the distribution of the current target vector yi\mathbf{y}_iyi​ is directly conditioned on the previous target vector yi−1\mathbf{y}_{i-1}yi−1​ and the previous hidden state ci−1\mathbf{c}_{i-1}ci−1​. Because the previous hidden state ci−1\mathbf{c}_{i-1}ci−1​ depends on all previous target vectors y0,…,yi−2\mathbf{y}_0, \ldots, \mathbf{y}_{i-2}y0​,…,yi−2​, it can be stated that the RNN-based decoder implicitly (e.g. indirectly) models the conditional distribution pθdec(yi∣Y0:i−1,c)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c})pθdec​​(yi​∣Y0:i−1​,c).

The space of possible target vector sequences Y1:m\mathbf{Y}_{1:m}Y1:m​ is prohibitively large so that at inference, one has to rely on decoding methods 5{}^55 that efficiently sample high probability target vector sequences from pθdec(Y1:m∣c)p_{\theta_{dec}}(\mathbf{Y}_{1:m} |\mathbf{c})pθdec​​(Y1:m​∣c).

Given such a decoding method, during inference, the next input vector yi\mathbf{y}_iyi​ can then be sampled from pθdec(yi∣Y0:i−1,c)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c})pθdec​​(yi​∣Y0:i−1​,c) and is consequently appended to the input sequence so that the decoder RNN then models pθdec(yi+1∣Y0:i,c)p_{\theta_{\text{dec}}}(\mathbf{y}_{i+1} | \mathbf{Y}_{0: i}, \mathbf{c})pθdec​​(yi+1​∣Y0:i​,c) to sample the next input vector yi+1\mathbf{y}_{i+1}yi+1​ and so on in an auto-regressive fashion.

The EOS\text{EOS}EOS vector often represents the final input vector xn\mathbf{x}_nxn​ to "cue" the encoder that the input sequence has ended and also defines the end of the target sequence. As soon as the EOS\text{EOS}EOS is sampled from a logit vector, the generation is complete. The BOS\text{BOS}BOS vector represents the input vector y0\mathbf{y}_0y0​ fed to the decoder RNN at the very first decoding step. The RNN-based encoder-decoder model took the NLG community by storm. In 2016, Google announced to fully replace its heavily feature engineered translation service by a single RNN-based encoder-decoder model (see here).

Nevertheless, RNN-based encoder-decoder models have two pitfalls. First, RNNs suffer from the vanishing gradient problem, making it very difficult to capture long-range dependencies, cf. Hochreiter et al. (2001). Second, the inherent recurrent architecture of RNNs prevents efficient parallelization when encoding, cf. Vaswani et al. (2017).

In 2017, Vaswani et al. introduced the Transformer and thereby gave birth to transformer-based encoder-decoder models.

Analogous to RNN-based encoder-decoder models, transformer-based encoder-decoder models consist of an encoder and a decoder which are both stacks of residual attention blocks. The key innovation of transformer-based encoder-decoder models is that such residual attention blocks can process an input sequence X1:n\mathbf{X}_{1:n}X1:n​ of variable length nnn without exhibiting a recurrent structure. Not relying on a recurrent structure allows transformer-based encoder-decoders to be highly parallelizable, which makes the model orders of magnitude more computationally efficient than RNN-based encoder-decoder models on modern hardware.

As a reminder, to solve a sequence-to-sequence problem, we need to find a mapping of an input sequence X1:n\mathbf{X}_{1:n}X1:n​ to an output sequence Y1:m\mathbf{Y}_{1:m}Y1:m​ of variable length mmm. Let's see how transformer-based encoder-decoder models are used to find such a mapping.

Similar to RNN-based encoder-decoder models, the transformer-based encoder-decoder models define a conditional distribution of target vectors Y1:m\mathbf{Y}_{1:m}Y1:m​ given an input sequence X1:n\mathbf{X}_{1:n}X1:n​:

pθenc,θdec(Y1:m∣X1:n). p_{\theta_{\text{enc}}, \theta_{\text{dec}}}(\mathbf{Y}_{1:m} | \mathbf{X}_{1:n}). pθenc​,θdec​​(Y1:m​∣X1:n​).

The transformer-based encoder part encodes the input sequence X1:n\mathbf{X}_{1:n}X1:n​ to a sequence of hidden states X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​, thus defining the mapping:

fθenc:X1:n→X‾1:n. f_{\theta_{\text{enc}}}: \mathbf{X}_{1:n} \to \mathbf{\overline{X}}_{1:n}. fθenc​​:X1:n​→X1:n​.

The transformer-based decoder part then models the conditional probability distribution of the target vector sequence Y1:n\mathbf{Y}_{1:n}Y1:n​ given the sequence of encoded hidden states X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​:

pθdec(Y1:n∣X‾1:n). p_{\theta_{dec}}(\mathbf{Y}_{1:n} | \mathbf{\overline{X}}_{1:n}).pθdec​​(Y1:n​∣X1:n​).

By Bayes' rule, this distribution can be factorized to a product of conditional probability distribution of the target vector yi\mathbf{y}_iyi​ given the encoded hidden states X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ and all previous target vectors Y0:i−1\mathbf{Y}_{0:i-1}Y0:i−1​:

pθdec(Y1:n∣X‾1:n)=∏i=1npθdec(yi∣Y0:i−1,X‾1:n). p_{\theta_{dec}}(\mathbf{Y}_{1:n} | \mathbf{\overline{X}}_{1:n}) = \prod_{i=1}^{n} p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{\overline{X}}_{1:n}). pθdec​​(Y1:n​∣X1:n​)=i=1∏n​pθdec​​(yi​∣Y0:i−1​,X1:n​).

The transformer-based decoder hereby maps the sequence of encoded hidden states X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ and all previous target vectors Y0:i−1\mathbf{Y}_{0:i-1}Y0:i−1​ to the logit vector li\mathbf{l}_ili​. The logit vector li\mathbf{l}_ili​ is then processed by the softmax operation to define the conditional distribution pθdec(yi∣Y0:i−1,X‾1:n)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{\overline{X}}_{1:n})pθdec​​(yi​∣Y0:i−1​,X1:n​), just as it is done for RNN-based decoders. However, in contrast to RNN-based decoders, the distribution of the target vector yi\mathbf{y}_iyi​ is explicitly (or directly) conditioned on all previous target vectors y0,…,yi−1\mathbf{y}_0, \ldots, \mathbf{y}_{i-1}y0​,…,yi−1​ as we will see later in more detail. The 0th target vector y0\mathbf{y}_0y0​ is hereby represented by a special "begin-of-sentence" BOS\text{BOS}BOS vector.

To further understand the implications of the bi-directional self-attention layer, let's assume the following sentence is processed: "The house is beautiful and well located in the middle of the city where it is easily accessible by public transport". The word "it" refers to "house", which is 12 "positions away". In transformer-based encoders, the bi-directional self-attention layer performs a single mathematical operation to put the input vector of "house" into relation with the input vector of "it" (compare to the first illustration of this section). In contrast, in an RNN-based encoder, a word that is 12 "positions away", would require at least 12 mathematical operations meaning that in an RNN-based encoder a linear number of mathematical operations are required. This makes it much harder for an RNN-based encoder to model long-range contextual representations. Also, it becomes clear that a transformer-based encoder is much less prone to lose important information than an RNN-based encoder-decoder model because the sequence length of the encoding is kept the same, i.e. len(X1:n)=len(X‾1:n)=n\textbf{len}(\mathbf{X}_{1:n}) = \textbf{len}(\mathbf{\overline{X}}_{1:n}) = nlen(X1:n​)=len(X1:n​)=n, while an RNN compresses the length from ∗len((X1:n)=n*\textbf{len}((\mathbf{X}_{1:n}) = n∗len((X1:n​)=n to just len(c)=1\textbf{len}(\mathbf{c}) = 1len(c)=1, which makes it very difficult for RNNs to effectively encode long-range dependencies between input words.

We can summarize uni-directional self-attention as follows:

y′′i=V0:iSoftmax(K0:i⊺qi)+y′i.\mathbf{y''}_i = \mathbf{V}_{0: i} \textbf{Softmax}(\mathbf{K}_{0: i}^\intercal \mathbf{q}_i) + \mathbf{y'}_i. y′′i​=V0:i​Softmax(K0:i⊺​qi​)+y′i​.

Note that the index range of the key and value vectors is 0:i0:i0:i instead of 0:m−10: m-10:m−1 which would be the range of the key vectors in bi-directional self-attention.

Let's illustrate uni-directional self-attention for the input vector y′1\mathbf{y'}_1y′1​ for our example above.

As can be seen y′′1\mathbf{y''}_1y′′1​ only depends on y′0\mathbf{y'}_0y′0​ and y′1\mathbf{y'}_1y′1​. Therefore, we put the vector representation of the word "Ich", i.e. y′1\mathbf{y'}_1y′1​ only into relation with itself and the "BOS" target vector, i.e. y′0\mathbf{y'}_0y′0​, but not with the vector representation of the word "will", i.e. y′2\mathbf{y'}_2y′2​.

So why is it important that we use uni-directional self-attention in the decoder instead of bi-directional self-attention? As stated above, a transformer-based decoder defines a mapping from a sequence of input vector Y0:m−1\mathbf{Y}_{0: m-1}Y0:m−1​ to the logits corresponding to the next decoder input vectors, namely L1:m\mathbf{L}_{1:m}L1:m​. In our example, this means, e.g. that the input vector y1\mathbf{y}_1y1​ = "Ich" is mapped to the logit vector l2\mathbf{l}_2l2​, which is then used to predict the input vector y2\mathbf{y}_2y2​. Thus, if y′1\mathbf{y'}_1y′1​ would have access to the following input vectors Y′2:5\mathbf{Y'}_{2:5}Y′2:5​, the decoder would simply copy the vector representation of "will", i.e. y′2\mathbf{y'}_2y′2​, to be its output y′′1\mathbf{y''}_1y′′1​. This would be forwarded to the last layer so that the encoded output vector y‾1\mathbf{\overline{y}}_1y​1​ would essentially just correspond to the vector representation y2\mathbf{y}_2y2​.

This is obviously disadvantageous as the transformer-based decoder would never learn to predict the next word given all previous words, but just copy the target vector yi\mathbf{y}_iyi​ through the network to y‾i−1\mathbf{\overline{y}}_{i-1}y​i−1​ for all i∈{1,…,m}i \in \{1, \ldots, m \}i∈{1,…,m}. In order to define a conditional distribution of the next target vector, the distribution cannot be conditioned on the next target vector itself. It does not make much sense to predict yi\mathbf{y}_iyi​ from p(y∣Y0:i,X‾)p(\mathbf{y} | \mathbf{Y}_{0:i}, \mathbf{\overline{X}})p(y∣Y0:i​,X) because the distribution is conditioned on the target vector it is supposed to model. The uni-directional self-attention architecture, therefore, allows us to define a causal probability distribution, which is necessary to effectively model a conditional distribution of the next target vector.

Great! Now we can move to the layer that connects the encoder and decoder - the cross-attention mechanism!

The cross-attention layer takes two vector sequences as inputs: the outputs of the uni-directional self-attention layer, i.e. Y′′0:m−1\mathbf{Y''}_{0: m-1}Y′′0:m−1​ and the contextualized encoding vectors X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​. As in the self-attention layer, the query vectors q0,…,qm−1\mathbf{q}_0, \ldots, \mathbf{q}_{m-1}q0​,…,qm−1​ are projections of the output vectors of the previous layer, i.e. Y′′0:m−1\mathbf{Y''}_{0: m-1}Y′′0:m−1​. However, the key and value vectors k0,…,km−1\mathbf{k}_0, \ldots, \mathbf{k}_{m-1}k0​,…,km−1​ and v0,…,vm−1\mathbf{v}_0, \ldots, \mathbf{v}_{m-1}v0​,…,vm−1​ are projections of the contextualized encoding vectors X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​. Having defined key, value, and query vectors, a query vector qi\mathbf{q}_iqi​ is then compared to all key vectors and the corresponding score is used to weight the respective value vectors, just as is the case for bi-directional self-attention to give the output vector y′′′i\mathbf{y'''}_iy′′′i​ for all i∈0,…,m−1i \in {0, \ldots, m-1}i∈0,…,m−1. Cross-attention can be summarized as follows:

y′′′i=V1:nSoftmax(K1:n⊺qi)+y′′i. \mathbf{y'''}_i = \mathbf{V}_{1:n} \textbf{Softmax}(\mathbf{K}_{1: n}^\intercal \mathbf{q}_i) + \mathbf{y''}_i. y′′′i​=V1:n​Softmax(K1:n⊺​qi​)+y′′i​.

Note that the index range of the key and value vectors is 1:n1:n1:n corresponding to the number of contextualized encoding vectors.

Let's visualize the cross-attention mechanism for the input vector y′′1\mathbf{y''}_1y′′1​ for our example above.

We can see that the query vector q1\mathbf{q}_1q1​ (shown in purple) is derived from y′′1\mathbf{y''}_1y′′1​(shown in red) and therefore relies on a vector representation of the word "Ich". The query vector q1\mathbf{q}_1q1​ is then compared to the key vectors k1,…,k7\mathbf{k}_1, \ldots, \mathbf{k}_7k1​,…,k7​ (shown in yellow) corresponding to the contextual encoding representation of all encoder input vectors X1:n\mathbf{X}_{1:n}X1:n​ = "I want to buy a car EOS". This puts the vector representation of "Ich" into direct relation with all encoder input vectors. Finally, the attention weights are multiplied by the value vectors v1,…,v7\mathbf{v}_1, \ldots, \mathbf{v}_7v1​,…,v7​ (shown in turquoise) to yield in addition to the input vector y′′1\mathbf{y''}_1y′′1​ the output vector y′′′1\mathbf{y'''}_1y′′′1​ (shown in dark red).

So intuitively, what happens here exactly? Each output vector y′′′i\mathbf{y'''}_iy′′′i​ is a weighted sum of all value projections of the encoder inputs v1,…,v7\mathbf{v}_{1}, \ldots, \mathbf{v}_7v1​,…,v7​ plus the input vector itself y′′i\mathbf{y''}_iy′′i​ (c.f. illustrated formula above). The key mechanism to understand is the following: Depending on how similar a query projection of the input decoder vector qi\mathbf{q}_iqi​ is to a key projection of the encoder input vector kj\mathbf{k}_jkj​, the more important is the value projection of the encoder input vector vj\mathbf{v}_jvj​. In loose terms this means, the more "related" a decoder input representation is to an encoder input representation, the more does the input representation influence the decoder output representation.

Cool! Now we can see how this architecture nicely conditions each output vector y′′′i\mathbf{y'''}_iy′′′i​ on the interaction between the encoder input vectors X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ and the input vector y′′i\mathbf{y''}_iy′′i​. Another important observation at this point is that the architecture is completely independent of the number nnn of contextualized encoding vectors X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ on which the output vector y′′′i\mathbf{y'''}_iy′′′i​ is conditioned on. All projection matrices Wkcross\mathbf{W}^{\text{cross}}_{k}Wkcross​ and Wvcross\mathbf{W}^{\text{cross}}_{v}Wvcross​ to derive the key vectors k1,…,kn\mathbf{k}_1, \ldots, \mathbf{k}_nk1​,…,kn​ and the value vectors v1,…,vn\mathbf{v}_1, \ldots, \mathbf{v}_nv1​,…,vn​ respectively are shared across all positions 1,…,n1, \ldots, n1,…,n and all value vectors v1,…,vn \mathbf{v}_1, \ldots, \mathbf{v}_n v1​,…,vn​ are summed together to a single weighted averaged vector. Now it becomes obvious as well, why the transformer-based decoder does not suffer from the long-range dependency problem, the RNN-based decoder suffers from. Because each decoder logit vector is directly dependent on every single encoded output vector, the number of mathematical operations to compare the first encoded output vector and the last decoder logit vector amounts essentially to just one.

To conclude, the uni-directional self-attention layer is responsible for conditioning each output vector on all previous decoder input vectors and the current input vector and the cross-attention layer is responsible to further condition each output vector on all encoded input vectors.
