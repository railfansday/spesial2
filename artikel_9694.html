If the bot answers from your own content (retrieval-augmented generation), index the English and French versions of each page separately and tag each chunk with its language. Retrieve in the user's language first and fall back to the other language only when nothing relevant comes back.

Translating English chunks into French at answer time looks cheaper, but it produces inconsistent terms (product names, legal wording, prices written with the wrong decimal separator) and it makes it hard to show the source link in the right language.

Do the same for dates. Ask the model to return structured data (amount, date) and format it in your code, so a hallucinated format never reaches the user.

Quebec's Charter of the French Language, as amended by Bill 96, requires businesses to serve and inform consumers in French. For a chatbot this means French must be available, of equal quality, and not hidden behind an English-only first message. Test both languages with the same test set:

Every Canadian business we work with asks the same question: what happens when the bot can't answer? Give it a tool that creates a ticket or sends the transcript to a shared inbox, in the user's language, and say so in the reply ("Je transmets votre question à notre équipe…").

Log, for each conversation: locale, retrieved chunk IDs, whether a handoff happened, and the model version. That is enough to debug most bad answers without storing more personal data than you need.

Do I need a separate model for French? No. Current general models handle Canadian French well. What matters is French source content and a French test set.

Can I host the chatbot data in Canada? Many cloud providers offer Canadian regions for databases and logs. Model APIs vary, so check the provider's data-residency options and write down where data goes.

Is a chatbot disclosure required? Telling users they are talking to an automated assistant is good practice and expected under the OPC principles. Put it in the first message.
