PostgreSQL Fix Requires Server Updates and Rebuilding C Extensions

Tanggal: 2026-11-19

Posted on Nov 19 • Originally published at tmgs.vn

Updating PostgreSQL alone is insufficient to fully address a type confusion vulnerability that allows database users with object creation privileges to execute code on the server. According to The Hacker News, administrators must also rebuild every installed extension written in C to obtain full protection.

The executed code runs with the privileges of the operating system account running PostgreSQL. This establishes the impact described in the article; it does not establish execution with the operating system’s highest administrative privileges.

Researcher Mehmet Ince described a working exploit and demonstrated it on PostgreSQL 18.6. However, the PostgreSQL Global Development Group has not reported any attacks using the vulnerability. The demonstration supports prioritizing remediation, but does not establish that a particular organization has been compromised.

Affected releases are versions before 18.7, 17.12, 16.16, 15.20 and 14.25 in their respective branches. The corresponding update targets are 18.7, 17.12, 16.16, 15.20 or 14.25, depending on the major version in use.

For organizations using an external database administrator, TMGS recommends explicitly assigning responsibility for rebuilding extensions, testing and delivering results. A statement that PostgreSQL has been updated does not establish that the extension work required for full protection is complete.
