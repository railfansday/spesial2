8 of 16 Pass. 2 of 16 Lie to You. A Decision Framework for Buying a Tool You Can Only Demo in a Browser

Tanggal: 2026-11-23

Here is the problem with buying developer tooling: the part you are allowed to touch before paying is never the part you are buying.

You get a textarea. It returns something that looks plausible. The vendor describes a model, an engine, a runtime. What you can actually test is a static page with a marketing story on it. That gap is where money gets wasted.

So I built a checklist for it, and I calibrated it on a real product: the USB Coding Expert demo — a bootable-USB coding assistant whose page offers a "Live Demo — Code Generator" panel. Type a request, pick Python / JavaScript / Bash / Solidity, get a snippet. The page claims it generates "real working code instantly."

I extracted the generator, ran all 16 possible outputs in real runtimes, and compiled the Solidity ones. 8 of 16 pass unchanged. 2 pass with a flag. 6 fail. And 2 of those 6 are the interesting kind of failure: the output tells you something happened when it did not.

The audit results are below. But the more useful part is the checklist — because it applies to every demo you will ever evaluate, including ones I have not looked at.
