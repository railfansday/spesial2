I put 7 Claude Code agents in my research lab's group chat with Switch. Here's how to set it up (and what broke on Windows)

Tanggal: 2026-11-07

Posted on Nov 7 • Edited on Nov 7 • Originally published at dev.to

I'm a PhD researcher. Every lab I've worked in runs on one group chat, and every Friday the professor asks the same three questions: What did we decide? Who is blocked? Is it really done? The answers exist, but they're scattered across meeting notes, more than 1000 of chat messages a week, papers someone shared once, and a git repo nobody reads.

For the Flip the Switch hackathon (WeMakeDevs × DevTools Academy × Switch), I built LabRoom: seven Claude Code agents that live in a lab's Mattermost chat, connected through one Switch room. This post covers what I built, how to set Switch up from zero, and every mistake I made along the way, so your first Switch project goes faster than mine did.

The lab in the demo is fictional: Dr. Maya Chen and five students building one small camera-trap CNN. Dr. Chen hasn't read the chat all day, so she asks the room:

@reporter I haven't read today's chat. One line per student: what did they do today, what do they think of the v0.4 plan, and is anyone waiting on someone?

The reporter agent answered in 7 seconds, one line per student, from the chat, the meeting transcript, the daily logs and git. Its last line was something nobody had noticed: Wei has been waiting on her since Nov 3. That's the whole idea: the PI asks instead of scrolling.

Two rules run through all of them: people approve every record, and nobody is ranked.

If you're new to Switch, these are the concepts I wish I'd understood on day one.

I did this on Windows 11 with Switch Console 0.40 and Switch server 0.31. The Windows build is early access, and these are the exact bumps I hit.

1. Docker Desktop first. The local Switch server runs Mattermost, Postgres and Elasticsearch in Docker. My Docker Desktop crashed on startup with a stale-socket error. Quitting Docker and renaming the run folder under %LOCALAPPDATA%\Docker (so Docker recreates it) fixed it.

2. Install Switch Console and start the local server. Home should say Running and list Mattermost under messaging apps. Your Mattermost login is under Home → Mattermost → Sign-in details.
