Tailwind CSS RTL in Next.js: logical utilities, the rtl: variant and what must never flip

Tanggal: 2026-11-10

Posted on Nov 10 • Originally published at aniq-ui.com • AI-assisted

We ship every Next.js template in English and Arabic, with a real right-to-left layout. After doing that across every website and dashboard we sell, the whole approach fits in one sentence:

Set dir on , write spacing and position with logical utilities (ms-4, not ml-4), and keep the rtl: variant for the few things logical properties cannot express.

This post is the practical version of that sentence, with code from real projects. Every class below was checked against Tailwind CSS 4.3.

Logical properties read the element's direction, the rtl: variant looks for it, and screen readers use lang to pick a voice. Put both on , not on a wrapper: dialogs, menus and toasts usually render in a portal under and only inherit a direction set above them.

With next-intl and the App Router, let app/[locale]/layout.tsx render :

Do not set dir in a useEffect. The server HTML then arrives left to right, paints that way, and flips after hydration: a visible jump on every Arabic page load.

ml-4 is margin-left in both languages. ms-4 is margin-inline-start: the left in English, the right in Arabic. One class, both directions.

Tailwind CSS 4.2 added inset-s-* and inset-e-* and deprecated start-* and end-*. The old names still compile to the same property, so existing code is fine.

What already flips without a new class: flex and grid rows, justify-start / justify-end, mx-*, px-*, and in Tailwind CSS 4 also space-x-* and divide-x. So never add flex-row-reverse "for Arabic": the row already reversed when the direction changed, and reversing it again puts it back in English order.

An input with an icon shows the pattern in one component:

Icon at start-4, text padded with ps-11. In Arabic both move to the right with no override.

Physical utilities are still right when the thing is physical: left-1/2 -translate-x-1/2 centres in both directions, and a before/after photo slider keeps "before" on the left in every language. Decide per element, and leave a comment so nobody "fixes" it later.

Transforms, gradients, transform origins, keyframes and icon meaning have no logical version. That is what rtl: and ltr: are for. In Tailwind CSS 4.3 they compile like this:

The :where() adds no specificity, and the selector matches the element's own direction, a dir="rtl" attribute, or any ancestor with dir="rtl". Keep that last part in mind (see the catch below).

Prefer -scale-x-100 (a true mirror) over rotate-180, which also turns the icon upside down. Flip arrows, chevrons and "view all" links. Do not flip play buttons, media progress bars, clocks or logos.

Keyboard arrows are behaviour. In tabs or a slider, the right arrow key should move towards the next item on screen, which is to the left in Arabic:

Because rtl: matches any dir="rtl" ancestor, it still applies inside a dir="ltr" element on an Arabic page. When you need the element's own direction, use an arbitrary variant on the :dir() pseudo-class:
