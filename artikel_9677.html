OpenTelemetry Java agent for Dynatrace: instrument an application and send its data

Tanggal: 2026-11-26

Posted on Nov 26 • Originally published at span.observer

Your team wants standard, portable instrumentation for a Spring Boot application without changing its code. It has no OneAgent on these containers, or it has chosen OpenTelemetry as the platform standard. The OpenTelemetry Java agent for Dynatrace meets that need: one JAR file added at JVM startup, and traces, metrics and logs flow over OTLP to Dynatrace.

Goal of this tutorial: download the agent, configure it with environment variables to send all three signals to Dynatrace, deploy it on a VM and then on Kubernetes, and check that the data arrives. The content applies to both Dynatrace SaaS and Dynatrace Managed; only the endpoint URL changes.

If OneAgent already monitors the same process, first read OneAgent and OpenTelemetry: avoiding duplicate spans. Two auto-instrumentations in one JVM produce duplicate spans.

In production, replace latest with a pinned version (for example download/v2.x.y/) so every build is reproducible, and test upgrades like any other dependency.

With the OpenTelemetry Operator, the Instrumentation resource automates this injection. For centralised export, point the endpoint at an OpenTelemetry Collector that holds the token instead.

You should see the application’s HTTP routes. For logs: fetch logs | filter service.name == "checkout" | limit 20. On Managed, the service appears in the services list and the traces in the distributed traces view; metrics are visible in the data explorer. The exact screens depend on your version: see the Dynatrace OpenTelemetry documentation.

Not for basic instrumentation: the agent automatically instruments common frameworks (HTTP, JDBC, messaging). Add the OpenTelemetry API only for business spans or attributes.

Direct export suits a test or a handful of services. Beyond that, a Collector centralises the token, filtering and retries.

The agent hooks into the appenders of common logging libraries (Logback, Log4j) when log export is on, with the related trace ID. Check your library in the list of supported instrumentations.

With one JAR and about ten variables, the OpenTelemetry Java agent sends traces, metrics and logs to Dynatrace without touching the code. Pin the version, enforce delta temporality, keep one instrumentation owner per process and verify in Grail. Your SLOs then rest on standard, portable data.
