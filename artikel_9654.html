Detect signatures in PDFs with Python

Tanggal: 2026-11-04

Posted on Nov 4 • Originally published at signature-detector.com

A contract PDF is not an image, but the detection result you want is still a list of boxes, one list per page. This post shows the PDF request body, the top-level response, and what a page with count 0 means.

The endpoint is the same one used for images:

POST https://signature-detector.com/api/detect

Send header x-api-key. The JSON body for a PDF is exactly one of pdfUrl or pdfBase64. Do not also send imageUrl or imageBase64 in that request.

pages, count, and creditsUsed sit on the response itself. They are not under result. An image call still uses result.detections. Branch on which body you sent.

count is the total across pages. pageCount is the number of pages. documentType is "pdf". signed is true when count is greater than zero. That flag means a visual mark was returned. It does not mean a certificate is present. confidenceThreshold is 0.1. PDF detection always uses that cutoff. An image request may send threshold from 0 to 1, and that field is not applied to PDF pages. A value outside 0 to 1 is HTTP 400.

The envelope also includes creditsRemaining and, when the row is stored, detectionId.

PDF processing is allowed 80 seconds on the server, so give your HTTP client a generous timeout, such as timeout=120 in requests.

Send pdfBase64 or pdfUrl, not both. A data-URL prefix on the base64 string is stripped if you include one. Raw base64 is what this snippet sends.

No page is rasterized or charged on that response.

A new PDF spends 1 credit per page, including pages with count 0. Images stay at 1 credit per request. A 10-page file is 10 credits, which is $0.001. Signup includes 10 credits, the minimum purchase is $1 (10,000 credits), and credits do not expire.

The cache key is pdf: plus the SHA-256 of the whole file. Sending those exact bytes again returns the stored summary with cached: true, creditsUsed: 0, and creditsRemaining unchanged. Saving the PDF again from an editor usually changes the bytes, and that copy is charged.

If rendering or detection fails after the charge, those credits are refunded. A timeout is HTTP 504.

Limits that fail before a charge: more than 20 pages or an encrypted PDF is HTTP 400, and a file over 20 MB is HTTP 413.

An empty page means no visual mark was returned. It does not mean a cryptographic PDF signature is absent. Plenty of electronically signed PDFs have a certificate and no ink. This API does not read the PDF signature dictionary. If you need that check, use a PDF library that inspects /Sig fields, and use this API for scanned or flattened marks.

Rendering to images is still a valid path, and it is the path that uses imageUrl or imageBase64 rather than the PDF fields. One request is one image. A 12-page packet is 12 requests if you send every page, and each uncached request spends 1 credit ($0.0001). That is the same credit total as one 12-page PDF.

The image response has result.detections and result.count. It does not have pages or creditsUsed. Don't share a parser between the two shapes without branching.

PDF pages always use 0.1. Filter confidence in Python if you want a stricter queue after the response. A cutoff such as 0.5 is a choice you make. It is not a PDF request field, and it is not a number this service publishes as an ideal operating point. Image requests can send threshold from 0 to 1.
