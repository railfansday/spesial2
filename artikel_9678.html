Tenant workspaces run on subdomains, like acme.your-app.com. Each tenant database holds that customer's own data: users, roles, menus, sessions, and whatever your product adds.

The domain of each request decides which tenant is active. Visit acme.your-app.com, and Laravel switches to Acme's database for that request.

Database per tenant is a good fit when customers expect their data to be truly separate, or when you might need to back up, move or delete one customer on its own. The trade-off is more moving parts: more databases to migrate and more to watch.

If most of your customers are small and you want the simplest setup, a single database with tenant_id can be enough.
