osFoundry से पिछला Claude Code सेशन कैसे ढूंढें और फिर से शुरू करें

Tanggal: 2026-11-07

इस गाइड के आख़िर तक पिछले हफ़्ते का एक Claude Code सेशन फिर से स्क्रीन पर होगा: osFoundry में प्रोजेक्ट का कोई शब्द टाइप करके आप उसे ढूंढते हैं, देखते हैं कि उसने क्या किया, और एक क्लिक से उसी फ़ोल्डर में claude --resume चला देते हैं जहाँ उसने काम किया था। इसी लिस्ट में आपके Codex सेशन भी हैं, और मशीन पर मौजूद दस और AI ऐप्स के सेशन भी। osFoundry कभी Claude Code से बात नहीं करता; वह सिर्फ़ वे फ़ाइलें पढ़ता है जो Claude Code पहले ही लिख चुका है।

ऊपर के chips हर उस ऐप के लिए एक-एक हैं जिसके सेशन मौजूद हैं, गिनती के साथ। osFoundry बारह ऐप्स पहचानता है: Claude Code, Claude ऐप, Codex CLI, Codex ऐप, Gemini CLI, Qwen Code, OpenCode, Copilot CLI, Cursor, Devin, Antigravity और Kiro। सिर्फ़ Claude Code के सेशन देखने के लिए Claude Code पर क्लिक करें। दाईं ओर का Apps मेन्यू इस डिवाइस के लिए किसी ऐप को बंद कर देता है, तब उसका फ़ोल्डर बिल्कुल नहीं पढ़ा जाता।

"Search titles, folders, branches" (title, फ़ोल्डर, branch में सर्च) में प्रोजेक्ट का कोई शब्द टाइप करें। सर्च title, फ़ोल्डर path, git branch, ऐप के नाम और session id से मिलान करती है। यह messages के अंदर सर्च नहीं करती, इसलिए प्रोजेक्ट या branch का नाम इस्तेमाल करें, Claude की कही कोई बात नहीं।

सेशन पर क्लिक करें। दाईं तरफ़ वह दिखता है जो Claude Code ने रिकॉर्ड किया, और पूरी बातचीत भी, जिसमें हर tool call अपनी अलग row में है।

"From the app" (ऐप से) पैनल बताता है कि दोबारा launch करने पर हर रिकॉर्ड की गई value के साथ क्या होगा: फ़ोल्डर वही रहता है, branch को फ़ोल्डर की मौजूदा branch से मिलाया जाता है, और model व approval दिखाए जाते हैं। अगर रिकॉर्ड किया गया approval mode CLI के default से कम पूछता है (Claude Code में default या plan के अलावा कोई भी), तो उसे तब तक रोक कर रखा जाता है जब तक आप उस launch के लिए उसे tick न करें।

अगर काम पुरानी branch पर ही होना चाहिए, तो Cancel दबाएँ और git switch खुद चलाएँ। Open anyway फ़ोल्डर में अभी जो है, उसी पर resume करता है। osFoundry यह जानने के लिए git -C rev-parse --abbrev-ref HEAD चलाता है, और कभी checkout नहीं चलाता।

उदाहरण। नीचे के सेशन demo data हैं, उसी फ़ॉर्मैट में जो ऐप पढ़ता है (एक developer के दो हफ़्ते, कई ऐप्स में); स्क्रीन और कमांड असली ऐप के हैं।

यह कमांड न किसी इंसान ने टाइप की है, न अंदाज़े से बनी है। डेस्कटॉप ऐप इसे रिकॉर्ड किए गए सेशन से बनाता है: claude --resume , साथ में --model और --effort अगर transcript में वे रिकॉर्ड हैं, और --permission-mode सिर्फ़ तब जब mode strict हो या आपने उसे tick किया हो। Codex सेशन के लिए वही बटन codex resume चलाता है, -m, -a और -s के साथ, उसी नियम से।

Open in Terminal के बगल में Continue here (यहीं जारी रखें) किसी Claude Code या Codex सेशन को CLI की जगह osFoundry chat के अंदर आगे बढ़ाता है।

osFoundry पढ़ता है, कंट्रोल नहीं लेता। हर ऐप का adapter सिर्फ़ उसी ऐप की session फ़ाइलें और SQLite indexes read-only खोलता है, और कभी कोई sign-in फ़ाइल नहीं। इसी वजह से कोई account connect करने की ज़रूरत नहीं: Claude Code का login Claude Code के पास ही रहता है, और resume किया गया सेशन आपके रूप में, CLI के अपने approval prompts के तहत चलता है।

सर्च जानबूझकर metadata तक सीमित है। Claude Code के transcripts बड़े हो जाते हैं (जिस Mac पर यह लिखा गया, उस पर median 168 MB है), इसलिए लिस्ट हर फ़ाइल की शुरुआती लाइनों और आख़िरी हिस्से से बनती है, और पूरा टेक्स्ट सिर्फ़ उसी एक सेशन का पढ़ा जाता है जिसे आप खोलते हैं।

Approvals अपने आप कभी ढीले नहीं होते। जो सेशन किसी permissive mode में चला था, वह CLI के default के साथ दोबारा खुलता है, जब तक आप उसी एक launch के लिए box tick न करें। Branch चेक होती है, बताई जाती है, और छोड़ दी जाती है। अगर सेशन का फ़ोल्डर अब मौजूद नहीं है, तो वह कहीं और नहीं खुलता।

जो चीज़ें सिर्फ़ किसी ऐप की अपनी window में होती हैं, वे वहीं रहती हैं। Codex ऐप का browser panel और review स्क्रीन, Claude ऐप के connectors और artifacts, और Cursor का editor सेशन पर नाम से दिखते हैं, पर terminal में नहीं आते।

कोई ऐसा सेशन खोलें जो अभी चल रहा है, और osFoundry में Sessions board देखें, जो बताता है कि osFoundry के अपने कौन-से agents काम कर रहे हैं, आपका इंतज़ार कर रहे हैं, या पूरे हो चुके हैं। अगर आपके पास अभी डेस्कटॉप ऐप नहीं है, तो Mac, Windows या Linux के लिए osFoundry डाउनलोड करें।
