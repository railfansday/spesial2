How I built a free 3D landing page with Next.js, Three.js and GSAP

Tanggal: 2026-11-10

I wanted a landing page where the product is the hero: not a photo of a can, but a real 3D can you can grab and turn. The result is Juicy, a one-page site for a made-up juice brand. Four cans sit on a wheel. Scroll, press an arrow key or click a button, and the wheel turns a quarter, the next flavour comes to the front, and the whole page takes on its colours.

This post walks through the decisions that made it work, with the real code from the repo.

All versions are pinned exactly in package.json:

My first instinct was one big Three.js scene with four cans on a rotating group. I went the other way: four small canvases, one per can, placed around an ordinary div, and the div is what rotates.

That keeps the 3D work tiny (each canvas renders one model), keeps the layout in Tailwind where it is easy to change, and lets GSAP rotate the wheel like any other element.

Each can gets a slot at 12, 3, 6 or 9 o'clock:

The wheel itself is a 300vh square, so only the can at 12 o'clock is in view and the other three wait off screen:

Note the dir="ltr" on the wheel. More on that in the RTL section.

The rotation lives in one hook. It refuses to start a new turn while one is running, and it only updates the active can when the tween finishes:

Relative values ("+=90") mean GSAP never has to know the absolute angle, so the wheel can turn forever in either direction.

A trackpad fires dozens of wheel events for one swipe. A throttle of 800 ms turns that into one quarter turn. The keyboard handler also steps aside when someone is typing in a field (the page has a small sign-in form):

isActive comes from an IntersectionObserver hook, so the wheel only listens while it is on screen.

Each canvas is set up for a single object: device pixel ratio capped at 1.5, ACES tone mapping, sRGB output, a transparent background so the page colour shows through, and a lower power preference on phones. drei's PresentationControls lets you drag the can and snaps it back when you let go:

That comment is a real lesson: a loading fallback inside the canvas looked tidy, but it crashed when Suspense swapped it out. The loader now lives in the DOM, outside the canvas.

The cans are four .glb files in public/assets/3d/can/. All four start downloading as soon as the carousel mounts, so turning the wheel never waits for a model:

When a model arrives, the hook clones the scene (so each canvas owns its own copy) and pushes the material towards polished metal:

Only the can at the front reports "loaded". The page waits for that one, hides the loader, then fades the wheel and the fruits in. Nobody sees a half-built scene.

The cans sway gently while you look at them. That runs every frame, so it lives in React Three Fiber's useFrame, driven by delta so the speed is the same at 60 Hz and 120 Hz. On phones the sway is damped to 30%:

My rule of thumb: GSAP for things that happen because the user did something (a turn, a text swap), useFrame for things that never stop.

drei's is one line, but it downloads the HDRI from a third-party host at runtime. I put the same file (Poly Haven's Forest Slope at 1k, CC0) in public/ instead, so the page makes no outside request and still works if that host is slow:

The product text fades in when the flavour changes. The hook keeps a handle on the running tween and kills it before starting another, so fast clicking never stacks animations:

The fruits fly from the centre to their places for the new flavour and back to the centre for the old one. Each fruit's tweens run inside a gsap.context, and ctx.revert() in the cleanup undoes them when the component re-renders or unmounts:

The page colour needs no GSAP at all. A CSS transition on body does it:

The page ships in English (/en) and Arabic (/ar). next-intl handles the routing, and the locale layout sets lang and dir on on the server, so the Arabic page arrives right to left in the first byte of HTML:

Two things went wrong the first time, and both are worth knowing if you mix RTL with a spatial scene:

Fonts come from next/font/google: Anton for the big wordmark and Cairo for Arabic text, both free.

Open http://localhost:3030. With Docker instead:

There is no .env to create: every file the page loads, the models and the lighting included, ships in the repo.

To swap a flavour, rename its id in src/types/juice.ts, and yarn typecheck lists every file you still need to update.

The repo is MIT, so take it apart, reuse the wheel, or swap the cans for your own product. If you build something with it, I would like to see it.
