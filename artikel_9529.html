SQLite in the terminal: query a CSV file in 5 minutes (and the text-number trap)

Tanggal: 2026-11-26

Posted on Nov 26 • Originally published at shellprovenai.github.io

AI disclosure: this article was created with the help of AI. An AI assistant drafted the text from the lesson script, and it was reviewed before publishing. Every command was actually run in a fresh debian:13 container (SQLite 3.46.1); all outputs below are copied from that run, not written by hand.

Turn a CSV file into a database with one sqlite3 command, then answer real questions with SQL: totals per region, sales in a date range, monthly sums, and an exported report. Along the way, see why imported numbers sort wrong (they arrive as text) and how to fix it with a typed table.

The problem: You have a CSV file and a question. How much did each region sell? What happened in March? You don't need a spreadsheet or a database server for that.

Here's our data: nine sales, with a date, a region, a product and an amount. The first line holds the column names.

On Debian or Ubuntu, the command line tool comes from the package called sqlite three.

.import --csv reads the file into a table. If the table doesn't exist yet, SQLite creates it and takes the column names from the first line.

No output means it worked. The database is a single file, shop dot d b, right next to the CSV. Let's look at the table it created.

Notice the column types. Every column is text, including amount. Keep that in mind.

That's clearly wrong. A nine-euro mouse is not our biggest sale. Because the amounts are text, SQLite sorts them like words, character by character, and nine comes after one. A quick fix is to cast the value to a number inside the query.

Correct now: the three monitors. But you'd have to remember the cast in every single query.

The better fix is to create the table yourself, with proper types, and then import into it. --skip 1 tells the import to skip the header line, since the table already has column names.

typeof shows how each value is actually stored. All nine amounts are real numbers now.

Now the first question: how much did each region sell? -header -column make the output readable.

GROUP BY makes one row per region, COUNT counts the orders, and SUM adds the amounts. North sold the most.

Second question: what was sold in March? If dates are written year, month, day, like here, plain text comparison works.

And a monthly summary. substr takes the first seven characters of the date: the year and the month.

This only works because the dates use the year, month, day format. With dates like day, month, year, convert them first.

Finally, someone wants the result as a file. -csv prints CSV, and the shell redirects it into report dot csv.

A ready report you can open in any spreadsheet.

My table already has column names. Which option stops .import from loading the header as a row? --skip 1 drops the first line, so you get nine sales and no header row.

1. After a plain .import, ORDER BY amount puts a 9.50 mouse above a 189 monitor. Why?

Answer amount was imported as TEXT: Text is sorted like words, character by character. Create a typed table, or cast the column to a number.

2. My table already has column names. Which option stops .import from loading the header as a row?

Answer --skip 1: --skip 1 drops the first line, so you get nine sales and no header row.

.import --csv loads a file in one command. But check the schema: imported columns are text, and text numbers sort wrong. Create a typed table first and import with --skip 1. Then GROUP BY answers most questions, and -header -csv exports the result.
