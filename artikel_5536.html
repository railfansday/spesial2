AI Is Writing Code Faster Than Security Can Review It, Finds New Linux Foundation Research Sponsored by ActiveState

Tanggal: 2026-11-09

Study reveals 58% of teams ship code faster than security review can keep up, as AI coding tools add dependencies that teams vet only about half the time

VANCOUVER, BC, Nov. 9, 2026 /PRNewswire/ -- ActiveState, a sponsor and contributor to a new Linux Foundation research study supported by the Open Source Security Foundation (OpenSSF) and LF AI & Data Foundation, today announced findings from the State of AI Impact on Software Security and Cybersecurity 2026, revealing a growing gap between the pace of AI-driven software development and organizations' ability to secure the code being produced. The study found that 58% of surveyed teams ship code faster than security reviews can keep up, while 60% say AI coding assistants have increased the number of external packages in their codebases. Yet teams review the indirect, or "transitive," dependencies introduced by those packages only about half the time.

These challenges are becoming more urgent as AI accelerates both code generation and vulnerability discovery, leaving organizations less time to identify and remediate security flaws before attackers exploit them. The October 2026 PHP2Shell vulnerabilities underscored the urgency, with emergency patches issued and exploitation attempts reported within hours of disclosure. As vulnerabilities can be identified and exploited at increasing speed, organizations face mounting pressure to ensure security reviews, dependency vetting, and remediation keep pace.

The survey of 172 security practitioners across companies and open source projects also found that AI is part of the solution, albeit with some trade-offs. Respondents credited AI-assisted tools with detecting 30% of the vulnerabilities they found in the past year, and 69% said the tools had meaningfully improved their security posture. On average, AI tools made security work 17% faster, but false-positive vulnerability reports increased practitioners' workloads by 30%, highlighting the need to balance AI-driven efficiency with effective security oversight.

"AI coding assistants don't just write code. They choose your dependencies, and this research shows teams are checking only about half of what comes along for the ride," said Abby Kearns, CEO of ActiveState. "That matches what we hear from customers every week. Slowing developers down won't fix it. The answer is to decide what's trusted before it reaches the codebase, so developers and their AI tools start from components security has already approved."

Together, the findings point to a need to make security responsibilities explicit and strengthen governance as AI adoption grows. Dedicated roles, clear policies, and properly implemented tools correlate with greater preparedness; the survey does not establish that those practices cause the difference.

"As AI accelerates software development, organizations need to be just as deliberate about how they govern and secure the code being produced," said Laura Guazzelli, Security Architect for AI/ML/LLM/Agentic Systems at OpenSSF. "That starts with understanding where AI is introducing risk into the software supply chain, establishing clear ownership for addressing it, and ensuring security practices can keep pace with how software is built."

The report recommends that organizations assign a clear owner for AI-related security threats, formalize AI security policies that include human review of generated code, and strengthen controls on direct and transitive dependencies. Building on those findings, ActiveState recommends governing open source at the point of intake, alongside scanning and review, so security teams decide which components enter the software supply chain before developers or AI assistants pull them in.
