Zero Crypto APIs MCP Body Matches and the Streamable HTTP Endpoint Behind Them

Tanggal: 2026-11-28

A package body search is a narrow way to find a server that may not reveal its package name. Crypto APIs publishes several MCP packages, but the network service is identified by its route and behavior as much as by an HTML body. The first measurement returned zero.

On 2026-11-27 at 23:43 UTC, ZoomEye was queried with http.body="cryptoapis-mcp" using sub_type=all, page 1, and page size 1. The request succeeded and returned zero matches. No transport error was converted into a zero.

The result means the selected index did not show that phrase in an HTTP body under this scope. It does not prove that no Streamable HTTP MCP service exists. The endpoint may return a generic JSON response, require authentication before exposing content, use a different package name, or run on a network absent from the index.

CVE-2026-138026 affected multiple Crypto APIs MCP packages below their fixed versions. When started with Streamable HTTP transport and an operator API key, the server bound 0.0.0.0, exposed /mcp, and lacked caller authentication. An unauthenticated attacker could invoke tools using the operator's upstream credential.

The CVE lists effects that include paid-credit use, account-data access, event subscription changes, and deletion of HD wallet xPubs. The package family is broad, so exposure depends on which tools the deployment enabled and what the upstream key can do.

Start with MCP client configurations and container command lines. Look for Streamable HTTP transport, bind addresses, package names, and /mcp routes. Inspect the effective listener rather than relying only on an internet query. Confirm that an MCP authentication layer rejects anonymous requests before tool discovery.

For owned deployments, upgrade each package to its corrected version. Use a dedicated upstream key with minimal account permissions. Disable wallet administration, broadcasts, and subscription changes if the agent only reads data. Put the endpoint behind a management network or authenticated proxy.

The zero body count can still be saved as a baseline. It should not be used to claim the software is absent. Try alternate, defensible fields such as a known route or response header only when the evidence supports the query. Do not substitute a broad vendor name and present it as a product fingerprint.

ZoomEye can help identify public web services when a fingerprint exists. The CVE here also concerns a local MCP protocol path and an upstream credential. The most useful inventory combines external observation with client configuration and API-key scope. A zero external result does not remove the need to test /mcp authentication on the systems already known to the team.
