A one-page model-substitution audit report: the template

Tanggal: 2026-11-12

"100% match" is not a claim you can argue with, which is exactly why it should not be in the header.

Two people in the comments of my last piece pushed this harder than the piece did. aiapikey, who runs a gateway, said the sample-size framing belongs in the report header, and that a record your own code can edit is an assertion, not evidence. ahmetozel said the gateway's route label is another claim to preserve and test, never a denominator. This is the report those two arguments imply. Fill in the brackets.

Zero mismatches in [n] requests. That bounds the substitution rate near [3/n] at 95% confidence (rule of three). Sampling rule: [rule]. Frame count: [N]. Coverage: [probe arm, %] of requested traffic.

A buyer can argue with the first sentence. "100% match" is a sentence a buyer can only trust. Put the sampling rule and the frame count beside the result, not in an appendix, so a reader can check the draw was not relabelled after the fact.

Never merge these into one "served model" column. If column 1 and column 2 diverge, that gap is the finding, not a data-cleaning problem. If you let the gateway's label stand in for the result, you have audited the gateway's paperwork.

Join id = hash(client request id, upstream request id, timestamp). Generated on write. Both sides can then join their own records later without trusting the other's id space.

For each envelope: hash it at write time, then anchor the hash somewhere the gateway's admin cannot rewrite. An append-only log, a timestamping authority, or a daily Merkle root mailed to the customer. A hash stored in a system you control and can edit proves nothing, and a reviewer will ask that question in the first five minutes.

Missing is not a zero. unattested is not a pass, and counting it as one inflates the match rate by exactly the amount nobody checked.

Attach raw records for the frame period: pre-normalization envelopes, anchor hashes, the routing log, and the join ids. Redact prompts and keys, not ids.

It cannot prove substitution by itself. It makes both sides' numbers arguable, which is the most a report can do without the vendor running an independent attestation. If a vendor's answer to this template is "we don't retain envelopes", that answer is itself the finding, and it belongs in the header next to the number they did give you.
