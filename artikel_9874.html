"Proof of use" as a requirement for open source contributions?

Tanggal: 2026-11-17

As an open source maintainer, I get a lot of AI slop PRs. Some of these have genuine value. Most address edge cases that almost never occur in real life. It's not that they're not fixing real problems, it's that they're fixing problems that nobody is ever likely to encounter.

I'm experimenting with "proof of use" as a requirement for submissions. Specifically, you need to show me that your project that depends on my project before I'll look at your PR.

"Proof of use" can be an existing open source project that imports mine (show me the git history!) or a clear description starting with "in our closed source project in production, we found that...".

The specific problem that I want to address is ensuring that contributions from people genuinely depending on my software are handled, while filtering out the OpenClaw/Github green square farming/drive-by LLM noise.

Alternative way to reduce green square farming is to not be on GitHub (or only be there as a read-only mirror), but rather on Codeberg or another less-mainstream more community-values-oriented host. But that sounds like a fine thing to put in CONTRIBUTING.md, sure.

Codeberg definitely feels like a safer space, but there's the pressure to host issues and more on github for ease of collaboration :(

Any system needing proof adds a verification burden to yourself. It might be less work to rely purely on your taste.

I think this is a decent idea, yeah. When I file issues against upstream projects from $work I try to include clear cases where we actually hit an issue.

I don't know if this is just turtles-all-the-way-down, but couldn't AI help you triage it?

I do this on closed source (I call them cold reads) and it's proven quite effective.

I mean it's your project. But if I use it and report a bug, and even go to the lengths of providing a patch and it gets rejected with this, chances are good you'll never see me again except complaining about your project.

Of course this might be worth it. But I'm relatively sure you'll remove most of the "trying to give something back" people. I operate under the premise of "Here's my code, hope it is useful to you, patches mostly welcome" and so I also contribute back like that.

To clarify, I've never provided an LLM patch, but I'm obviously biased if my contributions were useful. I'm not denying in any way that they may be drive-by, it's been a while that I fully associated with a project and did regular "maintenance" on it.
