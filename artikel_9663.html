Two Policy Rules to Give Your AI Coding Agents Before Anything Else

Tanggal: 2026-11-03

Most teams adopting AI coding agents start with trust settings: what can the agent see, what can it change. Before you tune anything else, we'd start with two rules.

An agent can propose a change, run tests and open a pull request. Shipping to production should still be a human decision, made with the evidence in front of them. A deny rule makes that explicit instead of hoping nobody wires it up.

Your CI configuration is what decides whether everything else is checked. A change to .github/workflows can quietly skip a test job or loosen a branch protection step. That makes CI files the highest-leverage target in the repo, for a buggy agent or a prompt injection alike. ask holds the change on an Approvals page until someone reviews it.
