How to export Framer CMS content: CSV, JSON or code

Tanggal: 2026-11-16

Posted on Nov 16 • Originally published at deframer.co

You can get content out of the Framer CMS in three ways: export a collection as a spreadsheet from the editor where Framer offers it, copy it with a plugin or by hand, or convert the published site, which writes every collection as typed JSON in src/cms/ with its records, rich text and images. A spreadsheet suits a one-off move into another tool. JSON from a conversion suits a site you'll keep running in code, because the records arrive already wired to the pages that render them.

This post compares the routes, shows what each gives you, and covers the tricky parts: rich text, images, references and locales. Deframer is an independent tool and is not affiliated with, endorsed or sponsored by Framer.

Framer's CMS has supported importing collections from CSV for a long time, and its editor has offered ways to get a collection out as a file. Menus and plan features change, so check Framer's own help pages for the current steps on your plan.

Use it when the destination is another CMS with a CSV importer and you don't need the pages.

Framer has a plugin ecosystem, and some plugins sync or export CMS collections to tools like Google Sheets, Airtable or Notion. Plugins vary in what they support and how they're maintained, so test one on a copy of a small collection first and check that rich text and images come through the way you need.

Manual copying is realistic only for a handful of items. It's also the only way to bring along drafts that were never published, whichever other route you choose.

A conversion takes a different approach: Deframer reads the CMS data the published site already serves and writes each collection as two files.

The detail pages are wired to these records and prerendered for every item, so the export is also a working site. The files are the same whichever framework you convert to: Next.js, TanStack Start, Astro, React Router or Vite. The full tour is in Framer CMS to JSON in Next.js.

If you only want the data, you can ignore the rest of the project and keep the JSON. Converting to Vite gives you the smallest project around it.

That shape is easy to walk with a script, which makes it simple to turn into Markdown, HTML or a headless CMS's own rich-text format. Moving a Framer blog to Markdown includes such a script.

Every image field holds src, srcSet, pixelWidth, pixelHeight and alt. If you're leaving Framer, don't rely on CDN URLs indefinitely: convert with "Assets in the project", or download the files with a script and rewrite the src values.

A field that references another collection points at the other record. Keep the record ids when you move to another system, so references can be re-linked.

On a multi-locale site, records that differ by language get their own file per locale, such as src/cms/blog.ja-jp.json, next to the default one. A spreadsheet export usually covers one locale at a time.

Only published items are on the published site, so only they appear in a conversion. Publish anything you want to keep first, or copy drafts by hand.
