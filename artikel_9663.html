Test “Not sure yet” as a real answer in an Astro form

Tanggal: 2026-11-19

An epoxy customer can see there is something on the concrete without knowing whether it is paint, sealer or another coating. In the existing planner, “Not sure yet” is a visible answer for both area and surface. Each answer occupies its own position in the flow and is displayed with its question’s summary label.

The client’s Map keys selections by step index. Two steps can store the same visible string and still round-trip independently. A Set of answer strings would collapse the two values. A dictionary keyed by the labels displayed on buttons would have a similar collision. The four-question sequence is fixed, so the index remains a useful address until a design introduces conditional insertion or reordering.

There’s no skip action on these questions. Before a click, the Map has no entry for that step. After an explicit unknown answer, the Map holds the displayed label. If a future API takes this data, use a stable value for unknown and make the required fields explicit in the schema. Test that an omitted surface fails validation while a deliberate unknown survives serialisation. The browser example tests the current distinction at the summary boundary and leaves any slab recommendation to an installer.

Inspect the two unknown answers separately when testing changes. Revisit Surface and pick Bare concrete. The Area value should still read Not sure yet when the final list is rebuilt.
