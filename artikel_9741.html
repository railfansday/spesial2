Coding agents can open more PRs in a day than your team can review in a week. An AI software factory is supposed to turn all that code into features your team can ship. In practice, this moves the bottleneck from writing code to checking it.

Below, we will discuss all eight building blocks, the tools that support them, and what happens when one is missing.

TL;DR: An AI software factory consists of multiple coding agents working in parallel loops, each fed by a queue of specs. While code generation scales with compute, verification doesn’t. As a result, the amount of autonomy you can safely give your agents depends on how well you can verify the running app. Unit tests and AI review bots check the code, but something independent still needs to check the product from the user's perspective.

An AI software factory is a system of coding agents running in parallel loops, fed by a queue of specs and tickets. Every change passes through automated checks and a review gate before it reaches production.

Say a coding agent ships a redesigned checkout flow. Unit tests pass, the review bot leaves two style comments, and CI is green. But on the preview deployment, the new layout pushes the saved-card selector below a sticky banner, preventing returning customers from selecting a card. Nothing in the diff looks wrong, but once the change has been merged, every returning customer faces the same problem.

This is the gap QA.tech, an AI testing platform, is built to address. Its QA agents receive a user goal ("pay with a saved card and see the confirmation") and interact with the live app much like a real user would. The test case is written as a goal, so a renamed selector doesn't automatically break it. A web or mobile test case can also check email and SMS or make API calls along the way. That means the checkout test can verify that the receipt email actually arrives.

For most teams, a fully dark factory is not the right goal. Osmani warns about comprehension debt, which he defines as "the widening gap between how much code exists and how much any human still understands." A dark factory adds to that debt as fast as it produces code, even while the tests remain green. That risk is particularly high in large, decade-old systems, which is where a lot of mid-market and enterprise teams work.
