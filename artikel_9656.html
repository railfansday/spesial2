Building a Browser-First Audio Cleanup Flow That Uploads Less

Tanggal: 2026-11-03

For a small speech-focused noise-reduction tool, we built the flow around a narrower contract: keep the original video in the browser, extract only its audio, process that audio, and put the cleaned track back under the original picture locally.

The first useful check happens on the device, before an upload starts.

For audio, the current flow accepts MP3, PCM WAV, M4A/AAC, up to 100 MB and 30 minutes. For video, it accepts an MP4 with H.264 video and AAC audio, up to 500 MB and 30 minutes. The container extension is not enough: a file named clip.mp4 can still contain an unsupported codec.

A local preflight check gives the user a clear failure message and avoids spending time uploading a file that cannot be processed. It also makes the support conversation more concrete: report unsupported_codec, not just “something went wrong.”

A preview is only useful if it predicts the full result. Our preview uses the first 30 seconds of the user’s recording with the same noise-reduction settings used for the full task. The user can compare the original and cleaned speech before deciding.

The other important step is showing the exact minutes needed before confirmation. The system does not charge or deduct minutes while the user is still listening to the preview. That separation keeps the product flow understandable:

The browser extracts the audio track and uploads only that derived audio. When the cleaned audio is ready, the browser matches it back to the original file and exports a new MP4 with the original picture.

This reduces upload size and avoids sending video frames that the noise model never needs. It also creates a clear limitation: the user must keep the original file available until export is finished. A browser app should explain that requirement instead of hiding it behind a generic download button.

Local assembly also needs explicit browser support. In our case, MP4 export is supported in current Chrome and Edge on Windows and macOS; other browsers can still download the cleaned WAV even when local MP4 export is unavailable.

Audio uploads are temporary work data, not a permanent media library. The service deletes uploaded audio within 24 hours at the latest, and unconfirmed full-file inputs sooner. Cleaned audio is also temporary and can be deleted earlier from the task page.

Failure handling should distinguish a job that failed before the AI provider started from a result the user simply dislikes. The first case can return reserved minutes once. The second is why the preview must be honest: an automatic refund cannot turn a poor result into a useful workflow.

The target is steady noise under speech: fan or air-conditioning hiss, microphone hum, and ordinary room ambience. It is not the same as music separation, de-reverberation, clipping repair, or removing another person who is speaking at the same time.

That boundary belongs on the upload page, not only in a help article. Users should know what to test before they spend minutes, and the preview should remain the final judge for their own recording.

Remove Background Noise offers a free 30-second preview for audio and video. The audio noise remover returns a cleaned WAV, while the video noise remover keeps the original picture on the device and processes only the extracted audio.

The useful design principle is simple: upload the smallest data object that the model actually needs, then make every limitation visible before the user commits.
