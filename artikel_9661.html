Pasting config into a serial console drops lines: why it happens and how to fix it

Tanggal: 2026-11-23

You paste 40 lines of config into a console session at 9600 baud. The first dozen land, then you get half-commands, "% Invalid input", or lines that silently vanish. Nothing is wrong with the cable.

A delay is a guess. The safest way is to send one line, wait until the device prompt comes back, then send the next. That's what an expect script does, and it's tedious to maintain.

Serial uses a 100 ms line delay by default, !sleep 500 in the file adds an explicit pause, and --wait-for-echo waits for the device to echo each line.
