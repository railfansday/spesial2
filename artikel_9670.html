Catch a stale opening caption with a small SRT test in Python

Tanggal: 2026-11-14

The opening of a caption tutorial shows “glaze,” and so does the final playback. At least that’s what you want. If the ending still says “glass” after you fixed the opening, a quick search for “glaze” won’t catch it. And “glass” belongs in the middle of the file, where you demonstrate the original error.

Give the check two ranges, one for the opening and one for the ending. Ask for the corrected cue exactly once in each. Leave the demonstration outside both ranges so you can change that part of the tutorial without breaking the check.

Disclosure: AI assisted the drafting of this tutorial. The included script and fixture were run locally.

Use a plain UTF-8 SRT export. The following example is a small local fixture, independent of a video project. Save it as sample.srt.

In this fixture the opening copy is entirely inside the first two seconds. The final segment starts at 42 seconds. Those are test values. On an actual job, use the times of the cut you are handing off. A source timecode from the raw recording will miss the shifted edit.

This script is dependency-free and runs on Python 3.9 or newer. It uses ordinary SRT numbering, blank lines, and comma-separated timestamps. It reads a UTF-8 BOM and supports multiple text lines within a cue. The expected phrase is compared to the whole cue after normalizing case and punctuation, so a caption containing additional words will fail the test. That choice is useful for a one-line fixture and may be too strict for a longer subtitle.

Now duplicate the file as stale.srt and change only the last cue text to “Glass.” Repeat the command with stale.srt. It reports CHECK closing: 0 exact matches for 'glaze' and exits with code 1. The earlier wrong caption in the tutorial remains outside the checked ranges, so it never affects either test. A malformed cue exits with code 2. In a build script those codes can distinguish an expected review failure from a fixture that needs repair.

After the script passes, open the actual export. It can still have the wrong SRT attached, the line can come in early, or the playback controls can cover the word. Play the opening and the end from the rendered media and listen across both boundaries. At phone size, inspect the lower area for any collision between sample captions, a tutorial label and the video player.

Some projects intentionally split the phrase across two cues. In that case set the expected text for each opening and closing cue or define a richer rule for adjacent cues. Avoid running a global substring search to compensate. It would hide the stale-copy failure this check exists to catch.
