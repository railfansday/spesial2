Bitcoin Lightning fix blocks a probe linking private channels to onchain funding

Tanggal: 2026-11-03

LDK’s fix blocks a funding-location probe that required connections to both endpoints of an unannounced channel.

Bitcoin Optech highlighted the change on October 30. An unannounced channel stays out of the public network map, but that alone did not prevent LDK’s message-forwarding lookup from confirming its funding link.

A real short-channel ID, or SCID, works like blockchain coordinates. The Lightning specification defines it using the block height, the transaction’s position within that block and the output’s position within that transaction. Together, those identify the particular Bitcoin output funding a channel.

An attacker can derive a candidate ID from an output’s location without yet knowing whether it belongs to a channel between the suspected nodes. The documented probe supplies that missing confirmation. It requires the attacker to connect to both endpoints and construct an onion-message path through them that returns to the attacker.

Before the fix, LDK’s channel lookup could resolve a real SCID even for an unannounced channel once its funding confirmed. If the message returned successfully, the attacker could confirm that the guessed output and the channel between those nodes matched.

The demonstrated leak therefore joins two pieces of information: a Bitcoin funding output and the Lightning nodes using it.

LDK now refuses to resolve an unannounced channel’s real SCID for onion-message forwarding. Valid aliases remain usable as alternative identifiers, so a sender can address the channel without using its real blockchain coordinates. The change closes this lookup route while preserving forwarding that uses an allowed alias.

The change is described in the pull request. Under BOLT 4’s onion-routing rules, an onion-message SCID must correspond to an announced identifier or a local alias.

The fix’s inclusion in installed wallet versions remains unverified. Users need confirmation from their wallet provider before assuming installed software has this protection.
