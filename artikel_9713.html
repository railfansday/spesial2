Terraform for Beginners: Build Cloud Infrastructure by Writing Simple Code

Tanggal: 2026-11-13

Imagine you spent a whole afternoon clicking around the Azure or AWS website to set up a server, a network, a database and a few security rules. It works. Well done.

Now your manager says: "Great, can you build exactly the same thing again for testing, and another copy in Europe?" Can you remember every click? Every setting? Every small box you ticked?

Most people cannot. That is the problem Terraform solves. Instead of clicking, you write down what you want in a simple text file. Terraform reads the file and builds it for you, the same way, every time.

Terraform is a tool that turns a simple text file into real cloud infrastructure.

This idea is called Infrastructure as Code, or IaC for short. Your servers, networks and databases are described in code, just like an app.

A good way to picture it is a building plan. An architect does not build a house by shouting instructions to workers one by one. She draws a plan. Builders follow the plan. If you want ten identical houses, you use the same plan ten times. Terraform files are your plan.

Terraform is made by a company called HashiCorp. It works with almost every cloud: AWS, Microsoft Azure, Google Cloud and hundreds of other services. You may also hear about OpenTofu, a free open source version that works in almost the same way. Everything you learn here applies to both.

Figure 1: You write the code, Terraform reads it, the provider talks to the cloud.

The most important idea: you describe what you want, not how to build it step by step. Terraform works out the steps.

Go to the official Terraform website from HashiCorp, download the version for your computer (Windows, Mac or Linux) and follow the install steps. On a Mac you can also use Homebrew, and on Windows you can use Chocolatey or winget.

If you see a version number, you are ready. I also recommend installing Visual Studio Code with the official HashiCorp Terraform extension. It colours your code and spots mistakes as you type.

The best way to learn Terraform without any risk of a cloud bill is to start with something local. We will ask Terraform to create a simple text file on your own computer. The steps are exactly the same as for a real server in the cloud.

Figure 2: init, plan, apply and destroy. You will use these every single day.

init gets everything ready. It notices you used local_file and downloads the provider that knows how to create files.

plan shows a preview. You should see something like "Plan: 1 to add, 0 to change, 0 to destroy". Nothing has been created yet. This is your chance to check before anything happens.

apply does the real work. Terraform shows the plan again and asks you to type yes. Type it and press Enter. Now look in your folder: there is a new file called hello.txt with your message inside. You just used Infrastructure as Code.

Change the content line to say "Hello again from Terraform!" and run terraform plan. Terraform notices the difference and tells you it will replace the file. Run terraform apply, type yes, and open the file again. It has been updated. You did not tell Terraform how to update it. You only changed what you wanted.

destroy deletes everything Terraform created in this folder. Type yes and hello.txt disappears. In the real cloud this is your best friend: one command and everything you built for practice is gone, so you are not paying for it.

Figure 3: Terraform compares what you want, what it remembers and what really exists.

Terraform can look scary at first, but the core idea is simple: write down what you want, check the plan, then let Terraform build it. The same file can build the same setup again tomorrow, next month or in another country.

Your challenge this week: create the hello.txt file with Terraform, change it, and destroy it. Those three commands, plan, apply and destroy, are the heart of everything you will ever do with Terraform.
