Reorder PDF Pages in C#: Custom Page Order and Full Document Reversal

Tanggal: 2026-11-10

After merging scanned files, you may find that the pages are in the wrong order, or you may want to move pages from the end of a document to the beginning. You can reorder PDF pages by specifying page indices, without first converting the PDF into images.

This article uses Spire.PDF for .NET to demonstrate two approaches: arranging pages in a custom order and reversing the page order of an entire document. Both examples use the same method, PdfPageCollection.ReArrange(int[] orderArray). The difference lies in how the ordering array is generated.

Spire.PDF for .NET is a library for reading, creating, and processing PDF files in .NET applications. This article uses its document loading, page reordering, and file saving APIs.

Before reordering pages, distinguish between the page positions shown in a PDF reader and the page indices used in code: indices start at 0, so page 1 corresponds to index 0, page 2 corresponds to index 1, and so on.

ReArrange() accepts an integer array. Each value represents a page index in the original document, and the sequence of values determines the new page order.

This article focuses on reordering while retaining all pages. The array should therefore include every page index from the original document exactly once, with values ranging from 0 to pdf.Pages.Count - 1.

Custom ordering is useful when you already know the desired page sequence, such as when swapping the first two pages or moving a cover page to the beginning of a document.

Reordering changes a page's position within the document. It does not rewrite page numbers in headers or footers to match the new positions. For example, if the original page 5 is moved to the beginning, any existing “Page 5” text on that page must be handled separately.

If the document contains a table of contents, bookmarks, or internal links, check that they point to the expected destinations after saving. A correct page sequence alone does not guarantee that all navigation elements have been updated accordingly.

When reordering while retaining all pages, check the array length, index range, and duplicate values before calling the method. The numbers in the array represent original page indices; do not enter the one-based page numbers shown in a PDF reader directly.

The examples save the results as new files to make comparison easier. When checking the output, confirm the page count first, then inspect the first page, the last page, and any pages that were moved.

Exception handling is omitted here to keep the core page reordering logic clear. Production applications should also handle invalid input paths, file reading failures, and unwritable output directories. They should ensure that the document is closed and related resources are released even if an exception occurs.

Also, Spire.PDF for .NET and Free Spire.PDF for .NET are different packages. When using a trial license or the free edition, check the licensing terms and processing limits for your specific version so that these restrictions are not mistaken for problems with the page reordering logic.

The key to reordering PDF pages with Spire.PDF for .NET is to construct an array of original page indices that represents the desired sequence. If the target order is already known, specify the array directly. To reverse an entire document, generate the indices from Pages.Count and reverse them using LINQ.

With either approach, remember that indices start at 0, and check both the actual page order and the document's navigation elements after saving.
