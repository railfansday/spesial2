I've always wondered how much one can trust a factory reset. Let's put a real case: I had my phone hacked by a nation state some weeks ago. Their spies held it physically for several hours, and they had the PIN. Of course, after that, I don't trust that phone at all. Why would I trust the "factory reset" that comes with Android? I expect they could also tamper the image with which it is reset. At this point, the whole phone is a brick, IMO, and so I bought a new one.

Factory reset Posted Nov 7, 2026 12:40 UTC (Sat) by NekkoDroid (guest, #176638) [Link] I am unsure if AOS does it like this, but what Lennart has always been working towards is that the UEFI verifies the kernel (UKI) using the public key, which then verifies the /usr/ partition (which is read-only), which then loads the rest. "the rest" here would be the factory reset part, which is the only really modifiable part (also EFI variables get reset). So say the nation state enrolled some kinda public key into the mutable part of the system (/var/ or possibly /etc/ but it sounds like it is also read-only) so that the system now also loads some of their system extensions or so, a factory reset would basically wipe those keys (and the extensions). /usr/ can't be enrolled, since that is pinned by the verity root hash and changes in the data would cause errors during reading by the kernel and the UKI is "pinned" by you (or I guess in the case of Amutable them) signing new UKIs. This is assuming you can prevent the nation state from enrolling their keys in your UEFI. But even if they did enroll their own keys in the UEFI the PCR values would be different, resulting in the mutable LUKS partitions not being automatically unlocked, so your mutable data is still inaccessible. So as long as the cryptography implementations are sound and not bypassed by some 0-days it should be sound for the most part. Unless they are able to get below the bootloader it should be fine (but at that point they don't even need your PIN). Do tell me if I maybe missed some attack vector which could possibly still exploit something.
