Loading TCMB Exchange Rates on a Schedule: Publication Time, Bayram Eves and Per-100 Yen

Tanggal: 2026-11-25

A nightly job that loads the Central Bank of the Republic of Türkiye's (TCMB) exchange rates looks trivial: fetch once a day, store, done. Three things break it in practice: when TCMB publishes, the days it doesn't, and how some currencies are quoted.

This post uses a year of TCMB publication dates from the AllRatesToday TCMB endpoint (25 November 2025 to 25 November 2026) to show where those traps are.

TCMB announces its indicative rates once per business day in the afternoon, around 15:30 Istanbul time. The API reports when the table usually lands and when it's safe to fetch:

So schedule after 13:25 UTC (16:25 Istanbul), not at 00:00. A job that runs at midnight still works, but it's loading yesterday afternoon's table and calling it today's. Use the rate_date from the response, never the job's run date.

The half-day eves (arife) are the trap. They're working days for most offices, so a job that only skips official full-day holidays will expect a table, not find one, and either fail or store yesterday's table under today's date. In this archive there was no table dated on any of the three eves.

The religious holidays move about 11 days earlier each year, so don't hard-code them. Two safer patterns:

Ask TCMB's calendar, not yours. The availability endpoint lists the dates TCMB actually published:

Or ask for the date you need and read back the date you got. The dated endpoint returns the table in force on that date. On a holiday, that's the last one published before it, flagged as such:

For accounting, that carry-forward is usually what you want: the rate in force on a bayram day is the last one published. Just store rate_date next to the amount, so the audit trail shows which table you used.

TCMB's own XML (https://www.tcmb.gov.tr/kurlar/today.xml) quotes some currencies per 100 units. On 25 November 2026:

That's TRY per 100 yen. A parser that ignores books JPY a hundred times too expensive. If you parse TCMB directly, divide by Unit every time. Don't special-case JPY; read the unit for each currency.

The API does this for you and always returns per-1 values: JPY/TRY comes back as 0.316512 buying and 0.318607 selling.

Each currency has a forex buying and a forex selling rate (TCMB also has banknote columns, which the API doesn't carry). In the API they're separate rows with type: "buy" and type: "sell":

Store both, or decide up front which one you need. Turkish VAT defaults to the forex buying rate. Ask for a single pair with ?source=USD&target=TRY&type=buy so the code says which one it means.

TCMB rates are the official indicative rates of the Central Bank of the Republic of Türkiye. Holiday names are our labels for the dates with no table, not TCMB's.
