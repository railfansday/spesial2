text-overflow: ellipsis Does Nothing in a Flex Row? Look at min-width

Tanggal: 2026-11-14

This layout bug shows up in a lot of UIs. A row has an icon, a long file name and a button. You want the name to end with "..." when space runs out. You add the usual three lines. Nothing happens. The name keeps its full length and shoves the button past the edge of the card.

Those three lines on .name are right. MDN points out that text-overflow cannot cause an overflow on its own. You pair it with overflow and white-space, and MDN's own example is overflow: hidden plus white-space: nowrap. Both are here.

This first version works, because .name is itself the flex item and overflow: hidden gives it a zero minimum.

So why no dots? In many real layouts, the text is not the flex item. It sits one level deeper.

Now .meta is the flex item in the row. It has no overflow of its own. That one detail is the whole bug.

Every flex item starts with min-width: auto. For flex items, auto does not mean zero.

Section 4.5 of the CSS Flexbox spec covers this. A flex item's automatic minimum width comes from its content, unless the item is a scroll container. MDN's min-width page says the same thing in shorter words: for flex items, auto resolves to a content-based size, and a scroll container gets a minimum of 0.

What does "based on content" mean for one long line of text that cannot wrap? The smallest the item may get is the full width of that line. So:

flex-shrink is still on, by the way. It just cannot shrink an item below its minimum size.

Give the flex item that holds the text a zero minimum:

Now .meta can shrink below its content width. .name inside it gets a real, narrow width, its text overflows, and the ellipsis shows up.

Another way is overflow: hidden on .meta. That turns it into a scroll container, and per the spec and MDN, a scroll container's automatic minimum is 0. We prefer min-width: 0 for this case. It states the intent directly, and it does not hide parts of .meta's children that paint past its edges, such as a child's focus ring.

One note from reading the docs: MDN says overflow: clip does not create a scroll container, while hidden does. So we would not expect overflow: clip on .meta to reset the minimum. Use min-width: 0 or overflow: hidden here.

If the text sits inside several nested flex containers, each flex item between the row and the text can hold the line open. Put min-width: 0 on each flex item on that path, not only the one nearest the text.

These properties are well supported. MDN lists min-width, overflow and text-overflow as Baseline widely available since July 2015, and flex-shrink since September 2015.
