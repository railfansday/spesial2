I built 67 file tools that never upload your files. Here's how the browser does it all

Tanggal: 2026-11-26

Disclosure: I'm the founder of Capy Files. This post is about how it works, including the parts that were hard.

Most "free online PDF tools" work the same way: you upload your file to their server, they process it, you download the result. That's fine for a meme. It's less fine for a payslip, a contract, a medical letter or a client's tax return.

So I wanted to see how far a browser can go on its own. The answer turned out to be: almost all the way. Capy Files does PDF editing, redaction, compression, video trimming, background removal, OCR and transcription entirely on your device. The server never sees a file.

Everything happens in Web Workers, so the page stays responsive, and every engine is WebAssembly or a browser API:

The site itself is a pre-rendered React app on Cloudflare. The server's only jobs are serving files, sign-in and payments.

Model downloads. "No upload" for AI means the model comes to you instead. The background-removal model is ~86 MB, and Whisper is bigger. They're cached after the first run, but asking someone for 86 MB before they've seen a single result is a lot. So the AI pages now show a real result from a sample file before anything downloads.

Memory on phones. A 2 GB video can't sit in memory on a phone. Lots of the media work is about streaming instead of loading whole files, and about saying clearly when a device simply can't do a job.

Cross-origin isolation. Some engines need SharedArrayBuffer, which needs COOP/COEP headers, which then break third-party embeds and sign-in popups. Tool pages are isolated; the login and checkout pages aren't.

Updates vs. open tabs. This one bit me this week. Each tool starts a fresh worker per job, from a file whose name is hashed per build. Someone with a tab left open across a few deploys pressed "Cut" twelve times and got a crash every time, because their version's worker file no longer existed on the server. The fix: each deploy keeps the last week's versions around, and a tab older than that is told to reload instead of being blamed for running out of memory.

Offline. A service worker caches the app shell and the everyday engines, so the common tools work offline from the first visit, not just after you've used them once.

Most tools are free with no account. Some heavier jobs (bigger batches, the best-quality AI models, saving certain edits without a watermark) are part of Pro. That's how I keep the lights on without selling data, since there's no data to sell.

Try it at capyfiles.com, and tell me what breaks.
