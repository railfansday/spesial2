Running PDF, OCR and AI tools entirely in the browser: what worked and what broke

Tanggal: 2026-11-13

Most "free online PDF tools" upload your file to a server, process it there, and delete it an hour or two later. I wanted the opposite for Utilkits: 99 everyday tools, where the PDF and image tools keep the file on your device. Here is how the browser does the heavy lifting, where it falls short, and the two bugs that taught me the most.

It's a Next.js 16 app, and the PDF, image and on-device AI tools run client-side:

The rule I hold myself to: if a tool can't run locally, the page says so. The redirect checker has to follow redirects from a server, so the how it works page lists it as an exception.

The models download once from Hugging Face and the browser caches them. The files themselves never leave the device.

The AI tools worked locally and failed in production on first use. The self-hosted transformers.web.min.js imported onnxruntime-web/webgpu by bare name, and no browser can resolve a bare module name without an import map. On top of that, the library's default is to fetch the onnxruntime .wasm engine from jsDelivr, which my content security policy blocks.

The fix: load transformers.min.js instead, copy the onnxruntime files from node_modules into /transformers/ before every build, and point env.backends.onnx.wasm.wasmPaths at that folder.

That fix had its own trap. Set wasmPaths on the existing settings object; don't replace the object. The runtime keeps a reference to the original, so assigning a new object does nothing and the engine still comes from the CDN.

The background remover also "worked" in development and never in production. Transformers.js 4 has no U2NetImageProcessor, and my code read an output name the model doesn't have.

The preparation is a set of pure functions, so the same code runs in the worker and in Node unit tests.

The badge also suggests the real test: load the page, turn off Wi-Fi, run the tool. If it still works, your file had nowhere to go.

Everything is at utilkits.com. The single-file tools are free, with no account. If you catch a tool sending your file anywhere, tell me in the comments.
