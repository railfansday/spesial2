把 AI CLI 包成 OpenAI 相容 API：從 stdin、JSON 輸出到逾時處理（附可跑範例）

Tanggal: 2026-11-05

一句話結論：把 CLI 接上 HTTP，核心是輸入、程序生命週期和輸出格式；路徑叫 /v1/chat/completions，不代表已經支援整份協定。

終端機裡已經有一個能回答問題的 AI CLI，但想接的程式只會送 HTTP 請求，兩邊講的是不同語言。

最先想到的是收到問題後跑一次 CLI，再把答案回傳。真的開始接才發現，容易出錯的地方全在中間：長 prompt 要怎麼傳？CLI 印出的 JSON 哪一段才是答案？指令卡住時，HTTP 要等多久？

這篇把實際包裝服務用到的做法縮成一個能在本機跑的範例。先用假的 CLI 驗證程序與協定，不需要模型金鑰，也不會消耗模型用量。

有實測的是 Python 包裝流程，沒有在這次測試中呼叫真實模型。 換成真實 CLI 時，登入、旗標與輸出格式仍要另外核對。

範例只接受一則文字 user 訊息，回傳一次完整 JSON。model 固定用 cli-demo，只是這個服務的識別名稱。

串流、工具呼叫、圖片、多輪歷史與其他參數，都明確拒絕。這樣呼叫端才不會以為參數已生效，實際卻被悄悄忽略。

OpenAI 的 Chat Completions 文件 定義了請求與回應欄位；這裡只實作其中一小部分，目的是讓需要「送一段文字、拿一段答案」的 HTTP 客戶端能接進來。

這個 result 是假 CLI 的格式，跟 HTTP 回應裡的 choices 是兩層不同的東西。包裝服務要負責轉換。

流程很直接：檢查請求，將文字送進 CLI 的 stdin，確認程序成功退出，再解析 result，最後包進 choices[0].message.content。

不把 CLI 的完整 stderr 直接回傳，避免把本機路徑或診斷細節送給呼叫端。實際服務可在受控的伺服器日誌記錄錯誤種類與耗時，不必把 prompt 全文一起記下來。

原本的服務曾把很長的上下文塞進 argv，碰到 Argument list too long。命令列有系統限制，不適合拿來搬大量文字。

input 透過 stdin 傳入，命令本身用參數陣列，也沒有開 shell=True。所以文字中的 $() 或反引號會當成普通內容傳給 CLI，不會先被包裝層當 shell 指令執行。這不代表 CLI 本身不能使用工具，兩者要分開看。Python subprocess 文件 有各參數的行為。

這次以 20 萬個 ASCII 字元實測，假 CLI 回報收到完整的 200,000 個字元。它驗證的是傳輸方式，不代表真實模型的 context window 一定裝得下。

有的 CLI 回一整個 JSON，有的回 JSONL，也就是一行一個事件。啟動訊息、工具結果與最後答案，不能全部原封不動塞進 content。

範例只接受 {"result":"文字"}，缺欄位、空答案或 is_error: true 都回 502。換成 JSONL 型 CLI，就要另外寫事件解析器，找出最後的 assistant 訊息，不能只拿最後一行。

例如 Claude Code 非互動模式 提供 -p 與結構化輸出；如果要接它，可將命令改成參數陣列 ['claude', '-p', '--output-format', 'json']，再依所用版本的輸出確認解析器。這是接入示意，本文沒有實測這個真實 CLI 的呼叫，也沒有處理它的登入流程。

CLI 非零退出時，不能照樣回 200，再把「發生錯誤」當成模型答案。就算退出碼是零，也要檢查應用層錯誤與答案格式。

check=True 負責非零退出，後面的 JSON 驗證負責輸出內容。兩關都過了，才回成功。

逾時也是同樣的道理。模型可能慢，但請求不能無限等下去；呼叫端的等待時間也要比這裡的 CLI timeout 留出一些餘裕。若 CLI 還會產生其他子程序，則要另做整組程序的清理，不能假設直接子程序結束就全部結束。

這份範例只綁 127.0.0.1，使用標準函式庫的簡單 HTTP server，依序處理請求。它沒有驗證身分、請求讀取期限、輸出大小限制或正式的並行管理，適合本機理解流程，不能直接當成公開服務。

每次 HTTP 請求也都是新 CLI 呼叫，不會自動保留前一輪歷史。要支援多輪、工具或串流，必須逐項定義轉換與錯誤行為，不能只把請求欄位加進來就算完成。

當時的需求是讓原本只認 HTTP 的程式能呼叫既有 CLI，所以先加一層薄薄的轉接，保留已經能工作的執行方式。

若你需要的是模型供應商完整的 API 功能，直接使用原生 API 會少掉一層格式轉換。CLI 包裝的價值，是讓既有工具接得上；代價則是 CLI 旗標、輸出格式與程序生命週期，都變成這層服務要維護的事。
