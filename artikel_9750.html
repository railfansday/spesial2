How to Render and Query a 25 MB / 60,000-Node JSON Tree in the Browser at 60 FPS

If you have ever pasted a 10 MB JSON response into a browser-based JSON viewer and watched the tab freeze with an "Aw, Snap! Out of Memory" crash, the culprit is almost never JSON.parse() itself.

In V8, parsing 10 MB of JSON takes ~60 milliseconds. What kills the browser tab is DOM node explosion and main-thread blocking:

Here is how we architected a client-side JSON workbench that formats, repairs, queries, and renders up to 25 MB payloads at 60 FPS using Web Workers, flat tree virtualization, and a 4-stage dirty-JSON repair pipeline.

For small payloads under 256 KB, synchronous parsing on the main thread takes less than 4 ms. Once a payload crosses 256 KB (up to our 25 MB browser safety ceiling), every heavy operation—strict parsing, lexical diagnostics, recursive key sorting, and stats calculation—should run off the main thread:

By serializing the worker script into a Blob URL (URL.createObjectURL(new Blob([workerSource]))), the worker runs 100% locally in the browser without requiring external network fetches, keeping the main UI thread responsive while typing or scrolling.

    A naive .replace(/'/g, '"') corrupts strings that contain apostrophes ("Don't"). Instead, a deterministic 4-pass character lexer (repairJson) tracks string context so it only converts outer single quotes while escaping internal double quotes (\"), strips comments outside string literals, quotes bare identifier keys, and strips trailing commas.
