A model response is not authorization

Tanggal: 2026-11-17

The moment an AI application can act — look up a record, update a ticket, issue a refund, send a message — every model response becomes part of a security-sensitive workflow. And the most common design mistake I see is treating the model's output as the decision.

A model response is not authorization. A valid tool call is not proof the action should execute. Those two sentences organize everything below.

A gateway sits between your application and the model providers, and it is genuinely good at request-shaped questions:

Whether this user may touch that record. Whether this refund is within policy. Whether this tool may change state at all. Those decisions need tenant data and business rules that live only in the application, so the application handles every tool call as untrusted input, in a fixed order:

Tools belong in an explicit registry, tiered by risk: read-only lookups at the bottom, destructive actions at the top behind approval and step-up authentication. The model never invents a tool name, and there is no generic tool that reaches the database.

Structured output is parseable, not trustworthy. Validate required fields, enums, ranges, lengths, unknown fields under strict schemas, tenant identifiers — and the business rules. Authorize after schema validation, because a well-formed identifier does not prove the caller owns the record. Test the rejection set on purpose: missing field, invented enum value, out-of-range number, extra property, and the response that is perfectly valid and belongs to a different tenant. Replay those fixtures whenever a prompt, model or routing rule changes.

Begin with a low-risk, read-only workflow — classification, lookup. Wire the key and a small registry, validate arguments and final JSON, review the metadata. Expand gradually to approved write actions. The gateway gives those controls a clean boundary and a log that can tell a rejected key from a blocked prompt from an unauthorized action; it does not replace the controls themselves, and honest designs say so.

The full design — decision tables, the key checklist, the worked validation pipeline — is in the nRouter engineering post "Secure LLM Gateway: API Keys, Tool Calls, and JSON Validation": https://nrouter.ai/blog/engineering/secure-llm-gateway-production-ai
