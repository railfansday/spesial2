🚀 Building Spring by Example V2: Completing Module 10 - Spring AI

Tanggal: 2026-11-26

When I started learning Spring, I noticed something about many of the tutorials I found.

They often showed how to use a feature, but not always why it worked or when you should choose one approach over another.

I learn best by building things and documenting what I discover, so I started a project called spring-by-example.

The idea is simple: instead of building one large application, I’m creating a collection of small, focused examples where each example explores a specific Spring concept with clear explanations, tests, and documentation.

I’m happy to say that I’ve now completed Module 10 - Spring AI. 🎉

This module introduced me to building AI-powered applications with Spring AI, from interacting with language models to working with embeddings, vector stores, retrieval-augmented generation, and AI tools.

One thing I really enjoyed about this module was discovering how Spring AI provides familiar Spring abstractions for working with AI models while hiding much of the complexity involved in communicating with different providers.

I started with the fundamentals and chat models, exploring how an application can send messages to a language model and retrieve responses using ChatClient and ChatModel.

Instead of hardcoding prompts directly into application logic, I learned how to externalize them and provide dynamic values using placeholders.

Structured output introduced another interesting concept.

Rather than working with unstructured text responses, I explored how Spring AI can convert model responses into Java objects using BeanOutputConverter.

This makes it easier to work with predictable response structures in application code.

Embeddings and vector stores were another important part of the module.

I explored how text can be converted into numerical vector representations that capture semantic meaning.

This led to vector stores, where I learned how to store documents and retrieve relevant information through similarity searches.

One of the most interesting examples was Retrieval-Augmented Generation (RAG).

RAG combines information retrieval with language model generation.

Instead of relying entirely on the model's existing knowledge, an application can retrieve relevant documents and provide them as context when generating an answer.

This helped me understand how AI applications can provide answers grounded in specific information sources.

This was particularly interesting because it demonstrated how an AI model can request that an application execute predefined functions.

For example, I built calculator tools that an AI assistant could use to perform arithmetic operations.

The important distinction is that the model does not execute the Java methods itself. It requests a tool call, and the application executes the corresponding method and returns the result.

Testing AI applications was another important part of the module.

I explored how to test services that use ChatClient, how to mock ChatModel responses, and how to verify prompt construction without making actual requests to an AI provider.

This was useful because AI applications introduce testing challenges that aren't always present in traditional Spring applications.

Finally, I explored Model Provider Integration.

Using Spring profiles, I could switch between providers through configuration without changing the application service implementation.

The same application service can interact with either provider through Spring AI's common abstractions.

That was a great way to finish the module because it brought together many of the concepts explored throughout the examples.

The goal wasn't simply to learn how to send a prompt to an AI model.

The bigger goal was to understand how Spring AI helps developers build applications that use language models, structured responses, semantic search, external tools, and different AI providers.
