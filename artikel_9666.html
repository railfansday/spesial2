Jira Bulk Change: Edit Many Work Items at Once

Tanggal: 2026-11-03

Posted on Nov 3 • Originally published at yamuno.com

Short answer: In Jira Cloud, search for the work items you want, then open More actions (•••) > Bulk change all work items. A four-step wizard lets you edit fields, transition, move, delete, or watch up to 1,000 work items in one go. You need the global Make bulk changes permission plus the normal permissions in each space, and there is no undo, so check your search before you start.

Bulk change is one of those Jira features people use a few times a year: closing out an old sprint, reassigning a leaver's work, fixing labels after an import, setting the missing resolution that keeps reports wrong. This guide walks through the native wizard, the JQL that makes it safe, the limits that trip people up, and what to do when the people who need bulk edits shouldn't be given the global permission.

Jira's bulk change works on the results of a search. From those results you pick one operation:

Which fields you can edit depends on the work items you selected. If they come from spaces with different field configurations, Jira only offers the fields they have in common.

The search is the most important part of a bulk change, because the wizard changes everything the search returns. A few patterns that come up often:

Done work items with no resolution. These are the reason many reports and dashboards miscount closed work; bulk edit the resolution to fix them.

Work left over in sprints that are already closed, ready to move to the backlog or a new sprint.

Open work nobody has touched in 90 days, a good candidate for a clean-up transition.

Before you run a bulk change, read the result count and open a few results. If the number surprises you, the query is wrong. Saving the query as a filter also leaves you a record of exactly which work items were changed.

The permission is the one that hurts most in practice. Admins are often careful with it, because one bulk change can touch a thousand work items across every space the person can edit. That leaves team leads and support staff asking an admin every time they need to reassign or relabel a batch of work.

Script Toolkit for Jira includes seven ready-made bulk tools for exactly that situation:

An admin decides who can use each tool under Jira settings > Apps > Script Toolkit > Tools: nobody (the default), admins only, admins and chosen groups, or everyone. So you can open Bulk Assign and Bulk Edit Labels to your team leads group without handing anyone a site-wide bulk permission.

People open Apps > Script Toolkit Tools, pick a tool, type a JQL query (it suggests fields and values and flags invalid JQL as you type), and run it on up to 5,000 work items per run. Two details make this safe to hand out:

Like the native wizard, these changes can't be undone, so the same habit applies: check the match count first. The tools don't move or delete work items; for those, use Jira's own bulk change. The tools guide covers access and limits, and the launch post shows what else the app does.

If the same bulk change keeps coming back, such as "every Monday, set the resolution on Done items that have none", don't run it by hand. Use Jira Automation:

Automation rules count toward your plan's automation usage, so very frequent rules over large searches are worth a second look. For logic a rule can't express, a Script Toolkit scheduled job runs your own JavaScript on a cron schedule.
