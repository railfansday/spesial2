Let OpenAI Codex deploy to production safely

Tanggal: 2026-11-26

Posted on Nov 26 • Originally published at gregale.dev

Originally published on gregale.dev. I build Gregale, so read this as a vendor's page. This post was written with AI assistance.

To let OpenAI Codex deploy to production safely, give Codex a scoped Gregale agent key in GREGALE_TOKEN rather than your personal login, allow network access for the CLI in Codex's sandbox if needed, and keep project deploy rules in AGENTS.md. Codex can then run --non-interactive --json deploys and health checks while Gregale's API enforces human approval on risky production changes, automatic 1%→100% canary rollbacks, non-code mutation undo, and a per-agent budget cap.

Export GREGALE_TOKEN in the environment Codex inherits instead of leaving it only on your personal login; without a --agent key, Gregale treats CLI writes as a human admin action and skips agent approvals and budget limits. If you run Codex inside workspace-write sandbox mode without outbound network enabled, add this to ~/.codex/config.toml so the CLI can reach api.gregale.dev:

--non-interactive --json guarantees Codex never stalls on prompts or OAuth tabs and always receives structured error codes on stderr.

How do I connect OpenAI Codex to Gregale safely?

Create a scoped --agent key with gregale key create codex-agent --agent, pass it in GREGALE_TOKEN, run gregale init --agents, and allow outbound CLI access in ~/.codex/config.toml under [sandbox_workspace_write] (network_access = true).

Why use --non-interactive --json with Codex?

In --non-interactive --json mode, gregale never pauses for prompts or opens a browser login flow and emits structured JSON error codes on stderr so Codex can inspect errors cleanly.

Can I undo scaling or env changes Codex made?

Yes. gregale mcp connection undo reverts non-code mutations such as scaling limits, environment variables, crons and domains logged over the last 7 days.
