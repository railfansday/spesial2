I built a tiny programming language for Halloween — then made property tests prove it behaves

Tanggal: 2026-11-23

This post is part of Kiroween 2026 — it's the story of my Skeleton Crew entry, CurseEngine.

The idea started with a grumble: every automation tool I rely on asks me to trust rules I can't read. Moderation bots, reminder workflows, digest jobs — the rule fires on real people, and the person accountable for it gets a settings page, not a sentence.

So I built the opposite. CurseEngine is a small language where a rule is one line of near-English:

A hand-written parser compiles that to an inspectable graph. A sandboxed executor runs it — no eval, no LLM making the call. And because a rule you can't rehearse is still a gamble, the same executor doubles as a simulator: run it over history and see what would have happened, with zero side effects. Every real action lands in an append-only log — the grimoire — where undo appends a reversal instead of erasing history.

One engine, three hosts: GrimMod (chat moderation — a raid bot muted on its third flagged message), Deadbeat (invoice chasing at 7/14/21 days, exactly once per tier), and a standup-digest rule-pack. After the engine's baseline commit, the apps were added with zero changes to the engine package. That diff is the whole Skeleton Crew argument, and it's checkable in the git history.

The part I did not expect: the property-based tests found the best bug. The suite runs 1,500 generated event streams through the live executor and the simulator and demands identical outcomes. On the first run it shrank a disagreement about stacked mutes down to a tiny example — a wrong assumption that my hand-written tests shared, which is exactly why they would never have caught it. The generators are wider now (hostile regex patterns, wrong-typed fields, webhook and timer curses), and the parity count is asserted inside the test so it can't silently shrink.

The build itself was spec-first in Kiro: four specs, steering files with three inviolables (no exfiltration, the simulator never executes side effects, every action is reversible), and a hook that re-runs the whole property suite every time a curse or fixture is saved — a hook I trust because we deliberately broke a fixture once and watched it fail. Total agent cost: about 50 of the 4,000 hackathon credits. Writing the decisions down turned out to be the cheap part's best friend.

Try it live: GrimMod and Deadbeat are both running (links in the repo), and the code is MIT at github.com/pintu544/curseengine. If you run a small community or chase invoices solo, I'd genuinely like to know which curse you'd write first.
